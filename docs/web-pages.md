# 웹 페이지 명세: 부산 청년 창업 길잡이

> 팀 피드백용 수정안. 상위 문서: [prd.md](prd.md), 기능 규칙: [features.md](features.md).
> 목적: 처음 접하는 사람의 이해와 진행을 돕되, 성인 이용자에게 자연스러운 표현을 사용한다.
> 문구 원칙: ‘창업 구상 정리 / 우선 준비사항 / 단계별 준비 안내 / 지역 지원 연결’.
> ‘오늘 할 작은 행동’, 성향에 따른 창업 적합성 판정, 성공을 보장하는 표현은 사용하지 않는다.

## 1. 페이지와 범위

| 페이지 | 경로 | 우선 | 기능 | 로그인 |
|---|---|---|---|---|
| 시작 메인 | / | P0 | F20 | 불필요 |
| 창업 탐색·구상 정리 | /mentor | P0 | F1~F3, F9 | 불필요 |
| 준비 안내·지역 연결 | /mentor 결과 단계 | P0 | F4~F7, F10~F12, F21 | 불필요 |
| 지역 기회 목록 | /programs | P1 | F18 | 불필요 |
| 지역 기회 상세 | /programs/:id | P1 | F4, F6, F7, F11, F18 | 불필요 |
| 계정 | /login, /signup, /me | P1 | F0, 계정 기반 F9 | 선택 |
| 팀 통계 | /admin | P1 | F14 | 팀만 |

기존 /mentor 경로를 유지해 개발 영향을 줄인다. P0에서는 결과 카드에 상세 정보를 펼쳐 보여줄 수 있으며 별도 상세 페이지가 필수는 아니다. /test, /apply/:programId, 외부 제출 진행은 P2로 미룬다.

## 2. 공통 디자인·동작

- 헤더: 로고, ‘창업 준비’, ‘지역 지원 살펴보기’(목록 구현 시), 선택적 로그인.
- 첫 화면과 대화 진입에 가입 팝업을 띄우지 않는다.
- 질문은 한 번에 하나. 직접 입력과 선택지를 함께 제공한다.
- ‘아직 모르겠어요’, ‘건너뛰기’, ‘이전’의 의미를 구분한다.
- B2B·BM·MVP 같은 약어를 질문의 전제로 사용하지 않는다. 필요하면 설명과 구체적 예시를 붙인다.
- 키보드로 선택·입력·진행할 수 있고, 입력 필드에 레이블과 오류 설명을 제공한다.
- 상태 배지는 글자도 함께 제공해 색만으로 의미를 구분하지 않는다.
- 휴대폰의 고정 버튼이 입력창·설명을 가리지 않게 한다. 핵심 버튼과 본문은 충분한 대비와 크기를 확보한다.
- 지역 데이터에는 공식 출처·확인일을 일관되게 표시한다.
- 대화 시작 전 서버·외부 AI 전송, 현재 기기 저장, 초기화 범위를 확인할 수 있게 한다.

## 3. 메인 /

**사용자가 이해할 내용:** 누구를 위한 서비스인지, 어떤 도움을 받는지, 얼마나 많은 정보를 준비해야 하는지.

| 순서 | 내용 | 행동 |
|---|---|---|
| 1 | 제목: ‘창업, 어디서 시작할지 몰라도 괜찮아요.’ | 창업 준비 시작하기 |
| 2 | 설명: ‘관심과 아이디어를 정리하고, 나에게 필요한 준비사항과 부산의 지원 경로를 확인하세요.’ | — |
| 3 | 선택 카드: ‘아이디어가 있어요 / 관심 분야부터 찾아볼게요’ | 선택한 상태로 /mentor |
| 4 | 결과 예시: 창업 구상·우선 준비사항·지역 지원 카드 | 실제 사용자 결과로 오인하지 않도록 예시 표시 |
| 5 | 이용 과정: 관심 입력 → 구상 정리 → 준비 안내·지역 연결 | — |
| 6 | 저장·데이터 안내와 공식 출처 | 안내 펼치기 |

모집 건수·성공 사례를 확보하지 않은 상태에서 실적처럼 표시하지 않는다. 성향 테스트와 자동 제출은 메인 주요 기능으로 소개하지 않는다.

## 4. /mentor — 단계 1: 시작 정보

진행 표시는 ‘관심·상황 → 구상 정리 → 준비 안내’. 대화 중에는 ‘질문 1/3’처럼 최대 범위를 알려준다.

### 아이디어가 있는 경우
- 질문: ‘어떤 일을 해보고 싶나요?’
- 입력: 200자 이내. 제품·서비스·매장 등 일상적인 설명을 허용.
- 예시 문구는 플레이스홀더나 별도 예시로 표시하며 답변으로 자동 저장하지 않음.

### 아이디어가 없는 경우
- 질문: ‘관심 있는 분야나 경험을 알려주세요.’
- 관심 선택과 직접 입력 제공. ‘아직 정하지 않았어요’를 선택하면 구체적인 경험 선택을 도와주되 결과 진입을 막지 않음.
- 활동 지역은 부산 구·군/미정. 사업자등록 주소를 요구하지 않음.

**진행 조건:** F1의 최소 선택·입력만 확인한다. 업종·고객·수익 구조의 미입력을 오류로 표시하지 않는다.
**주 버튼:** ‘구상 정리 시작’.

## 5. /mentor — 단계 2: 대화와 요약

### 5.1 대화
- 사용자 입력을 짧게 확인한 뒤 쉬운 질문 하나.
- 답변 영역: 직접 입력 / 선택지 / 아직 모르겠어요 / 건너뛰기.
- 최대 3개 질문. 이미 충분히 답했으면 ‘지금까지 내용 정리’ 제공.
- 정보 부족을 비난하거나 특정 분야 창업이 적성에 맞는다고 단정하지 않음.
- 응답 중 진행 상태 표시. 실패하면 입력을 유지하고 재시도·직접 정리 제공.

### 5.2 창업 구상 요약
| 항목 | 표시 |
|---|---|
| 관심과 구상 | 사용자가 설명한 하고 싶은 일 |
| 이용할 사람 | 직접 말한 대상 또는 미검증 제안 |
| 제공할 가치 | 해결할 불편이나 제공할 도움 |
| 확인할 사항 | 아직 모르는 부분과 검증이 필요한 가설 |

각 항목은 ‘직접 입력 / AI 제안·미검증 / 미정’을 표시한다. 항목별 수정과 ‘준비 안내 보기’ 제공. 요약 전체를 사업계획서 완성본으로 부르지 않는다.

## 6. /mentor — 단계 3: 준비 안내·지역 연결

### 6.1 상단 요약
제목은 ‘나의 창업 준비 방향’. 구상 요약과 준비 상태를 간단히 보여주고 ‘내용 수정’을 제공한다. 준비도를 퍼센트나 등급으로 평가하지 않는다.

### 6.2 우선 준비사항
- 우선 준비사항 1개를 먼저 보여줌.
- 구성: 제목 / 필요한 이유 / 진행 방법 / 정리할 결과.
- 후속 준비사항은 최대 2개로 제한하고 접어서 볼 수 있게 함.
- 사용자가 ‘준비 완료 표시’를 할 수 있으나 외부 상담·신청 완료와 혼동하지 않음.

### 6.3 부산에서 연결할 수 있는 지원
교육·상담·공간·지원사업 중 현재 준비에 관련 있는 최대 3개.

| 카드 요소 | 표시 기준 |
|---|---|
| 유형·기관·제목 | 공식 자료 기준 |
| 관련 이유 | 사용자가 확인한 구상·준비 상태와 연결 |
| 이용 대상 | 거주·연령·소속·사업자 등 명시 조건 |
| 얻을 도움 | 실제 제공 범위 |
| 이용 방법 | 공식 신청/문의 경로와 필요한 준비 |
| 상태 | 모집 중·종료·상시 안내·확인 필요 |
| 근거 | 원문 링크·확인일 |

**주 버튼:** ‘공식 안내 확인’ 또는 실제 자료에 맞는 ‘신청 방법 확인’.
자격 대조가 필요하면 ‘내 조건 확인’을 눌렀을 때 관련 항목만 요청한다. 이 질문을 건너뛰어도 요약과 준비 안내는 유지한다.

### 6.4 피드백과 저장
- 질문: ‘준비 방향을 정하는 데 도움이 되었나요?’
- 선택: 도움 됨 / 아쉬움 + 선택적 이유.
- 선택적 전후 문항: ‘현재 무엇부터 준비할지 알고 있다’ 1~5점.
- 요약·준비사항 복사, 기기 내 저장, 초기화.
- 계정 기능이 구현되면 결과를 본 뒤 선택적으로 가입 안내. 가입하지 않아도 결과를 읽고 복사 가능.
- 결과를 공개 링크로 자동 공유하지 않음.

## 7. 공통 예외 상태

| 상황 | 화면 처리 |
|---|---|
| 모르는 답변이 많음 | 미정 유지, 탐색·정보 확인 중심 준비 안내 |
| 적합한 지역 경로 없음 | ‘현재 확인된 자료에서 맞는 경로를 찾지 못했어요’와 준비 안내 |
| 조건 미입력·원문 불명확 | 추가 확인 필요와 필요한 질문 |
| 명시 조건 불일치 | 어떤 조건이 다른지 설명, 다른 경로 보기 |
| 기간 종료 | 현재 모집 카드에서 제외, 상세 접근 시 종료 표시 |
| AI 장애 | 답변 유지·재시도·직접 정리·검수된 지역 안내 |
| 수집 장애 | 마지막 확인일 표시, 새로 확인한 것처럼 표현하지 않음 |
| 요약 수정 | 기존 결과 갱신 안내, 준비 완료 표시 초기화 안내 |
| 새로고침 | 현재 기기 저장 범위에서 복구 |
| 초기화 | 지워지는 로컬 데이터 범위 확인 후 초기화 |

‘입력 조건 부합’은 최종 자격 확인이 아니라는 설명을 조건 결과 가까이에 둔다.

## 8. 보조 화면 — P1

### /programs, /programs/:id
유형·준비 단계·키워드 중심 탐색. 상세는 초보자에게 제공하는 도움과 이용 절차를 먼저 보여주고 원문을 연결한다. 로그인이나 지원서 자동 제출이 상세 진입 조건이 아니다.

### /login, /signup, /me
기존 계정 기능은 재방문·저장용이다. 가입 전 체험 데이터를 계정에 저장할 때 안내한다. 미구현 상태에서는 메뉴를 숨기고 현재 기기 저장만 제공한다.

### /admin
팀만 집계 지표를 볼 수 있다. 원문 대화·신원 정보는 통계 화면에 표시하지 않는다. 세션/기기 단위와 대상 사용자 인터뷰 수를 구분한다.

## 9. 피그마·개발 인계 기준

필수 시안은 3개 묶음: 메인, 탐색·대화, 결과. 각 묶음에 아이디어 없음·건너뛰기·오류·빈 결과 상태를 포함한다.

- 프론트는 공고 추천보다 구상 정리와 준비 안내를 결과 상단에 배치한다.
- AI·데이터 담당자는 사실/가설, 조건 상태, 모집 상태를 구분한 출력을 합의한다.
- 기획 담당자는 지역 경로의 공식 출처·이용 절차를 검수한다.
- 화면 완료 기준은 예쁜 정적 시안이 아니라 비회원으로 시작부터 결과·수정까지 진행되는 것이다.

## 10. 시연 흐름과 팀 피드백

시연: 관심 또는 막연한 구상 입력 → 쉬운 질문 → 구상 요약 → 수정 → 준비사항 → 출처 있는 부산 경로.
시연 인물의 경험·매출·의향을 실제 사용자 조사처럼 제시하지 않는다.
