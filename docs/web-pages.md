# 웹 페이지 명세: 해보까

> 팀 피드백용 수정안. 상위 문서: [prd.md](prd.md), 기능 규칙: [features.md](features.md).
> 목적: 처음 접하는 사람의 이해와 진행을 돕되, 성인 이용자에게 자연스러운 표현을 사용한다.
> 문구 원칙: ‘창업 구상 정리 / 우선 준비사항 / 단계별 준비 안내 / 지역 지원 연결’.
> ‘오늘 할 작은 행동’, 성향에 따른 창업 적합성 판정, 성공을 보장하는 표현은 사용하지 않는다.

## 2. 공통 디자인·동작

- 헤더: 로고(‘해보까 홈’), 이용 방법, K-Startup 외부 링크, AI 멘토, 공고 검색, 로그인 전에는 ‘로그인’·로그인 후에는 ‘내 정보’. 메뉴: 지원사업, AI 창업 상담, 창업 가이드, 내 활동. ‘AI 창업 상담’은 드롭다운 없이 바로 /mentor 로 간다. 관리자 링크는 없다.
- 첫 화면과 대화 진입에 가입 팝업을 띄우지 않는다.
- 질문은 한 번에 하나. 직접 입력과 선택지를 함께 제공한다.
- ‘아직 모르겠어요’, ‘건너뛰기’, ‘이전’의 의미를 구분한다.
- B2B·BM·MVP 같은 약어를 질문의 전제로 사용하지 않는다. 필요하면 설명과 구체적 예시를 붙인다.
- 키보드로 선택·입력·진행할 수 있고, 입력 필드에 레이블과 오류 설명을 제공한다.
- 상태 배지는 글자도 함께 제공해 색만으로 의미를 구분하지 않는다.
- 휴대폰의 고정 버튼이 입력창·설명을 가리지 않게 한다. 핵심 버튼과 본문은 충분한 대비와 크기를 확보한다.
- 지역 데이터에는 공식 출처·확인일을 일관되게 표시한다.
- 대화 시작 전 서버·외부 AI 전송, 현재 기기 저장, 초기화 범위를 확인할 수 있게 한다.

## 3. 메인 /

**사용자가 이해할 내용:** 누구를 위한 서비스인지, 어떤 도움을 받는지, 얼마나 많은 정보를 준비해야 하는지.

**현재 구성 (해보까 포털 디자인):** 자주 찾는 서비스(기본 4개, 펼치면 8개), 창업 단계 탭(탐색·구상·준비)과 단계별 링크, 원클릭 창업 상담, 마감 임박 공고. 검색창 아래에 ‘처음이라면’ 순서 칩(창업 유형 테스트 → AI 창업 상담 → 맞춤형 공고)과 이용 방법 링크가 있다. 아래 표는 처음 기획한 흐름이며 문구는 구현이 우선한다.

| 순서 | 내용 | 행동 |
|---|---|---|
| 1 | 제목: ‘창업, 어디서 시작할지 몰라도 괜찮아요.’ | 창업 준비 시작하기 |
| 2 | 설명: ‘관심과 아이디어를 정리하고, 나에게 필요한 준비사항과 부산의 지원 경로를 확인하세요.’ | — |
| 2-1 | 지역 설명: ‘내 구상을 부울경에서 어떻게 시작할 수 있을지 살펴보세요.’ 실제 제공 지역·자료 범위 표시 | — |
| 3 | 선택 카드: ‘아이디어가 있어요 / 관심 분야부터 찾아볼게요’ | 선택한 상태로 /mentor |
| 4 | 결과 예시: 창업 구상·우선 준비사항·지역 지원 카드 | 실제 사용자 결과로 오인하지 않도록 예시 표시 |
| 5 | 이용 과정: 관심 입력 → 구상 정리 → 준비 안내·지역 연결 | — |
| 6 | 저장·데이터 안내와 공식 출처 | 안내 펼치기 |

모집 건수·성공 사례를 확보하지 않은 상태에서 실적처럼 표시하지 않는다. 성향 테스트와 자동 제출은 메인 주요 기능으로 소개하지 않는다.

## 4. /mentor — 단계 1: 시작 정보

진행 표시는 ‘관심·상황 → 구상 정리 → 준비 안내’. 대화 중에는 ‘질문 1/3’처럼 최대 범위를 알려준다.

### 아이디어가 있는 경우
- 질문: ‘어떤 일을 해보고 싶나요?’
- 입력: 200자 이내. 제품·서비스·매장 등 일상적인 설명을 허용.
- 예시 문구는 플레이스홀더나 별도 예시로 표시하며 답변으로 자동 저장하지 않음.

### 아이디어가 없는 경우
- 질문: ‘관심 있는 분야나 경험을 알려주세요.’
- 기존 관심 선택 버튼을 조선·해양 / 자동차 / 항공 / 방산 / 수소·에너지 / 데이터센터 / AI / 2차전지 중심으로 구성한다. ‘아직 모름 / 기타’를 유지하고 긴 설명은 선택 후 보여준다.
- AI와 다른 산업을 함께 선택할 수 있다. 화면은 전문지식 확인 시험처럼 구성하지 않으며, 제품 개발·관련 업무 지원 서비스 등 관심 접점을 대화에서 구체화한다.
- 관심 선택과 직접 입력 제공. ‘아직 정하지 않았어요’를 선택하면 구체적인 경험 선택을 도와주되 결과 진입을 막지 않음.
- 사업자등록 주소를 요구하지 않음.

### 지역성 보완: 선택 입력 하나

(2026-11-27 변경) 활동 지역과 검토 지역을 지역 선택(RegionPicker) 한 칸으로 합쳤다. 부산 / 울산 / 경남을 누르면 구·군(경남은 시·군) 칩이 펼쳐지고 ‘미정’도 고를 수 있다. 필수 단계를 추가하지 않는다.

상담 화면 위에 ‘관심 공고’ 배너가 있으면(`/mentor?focus=<id>` 로 들어온 경우) 공고 제목과 ‘관심 공고 빼기’ 버튼을 보여 준다. 거주지·사업장 소재 요건은 지원 상세에서 별도 확인한다. 자료가 없는 지역은 ‘상세 지원 경로 준비 중’으로 표시하고 실제 지원 범위를 설명한다.

**진행 조건:** F1의 최소 선택·입력만 확인한다. 업종·고객·수익 구조의 미입력을 오류로 표시하지 않는다.
**주 버튼:** ‘구상 정리 시작’.

## 5. /mentor — 단계 2: 대화와 요약

### 5.1 대화
- 사용자 입력을 짧게 확인한 뒤 쉬운 질문 하나.
- 문제 카드를 선택했다면 제목·출처·근거 수준과 ‘다른 문제 보기’를 상단에 표시한다. 선택 이유·경험·알아보고 싶은 부분을 기존 최대 3개 질문 안에서 확인한다.
- 답변 영역: 직접 입력 / 선택지 / 아직 모르겠어요 / 건너뛰기.
- 최대 3개 질문. 이미 충분히 답했으면 ‘지금까지 내용 정리’ 제공. 요약 화면의 ‘AI와 더 이야기하기’로 같은 상담에서 질문을 이어 받을 수 있고, 한 상담은 최대 12문항이다. 답을 보낼 때마다 이번 주 상담 채팅 1회를 쓴다 (한 주 12회, 일요일 0시 한국 시간에 다시 채움).
- 정보 부족을 비난하거나 특정 분야 창업이 적성에 맞는다고 단정하지 않음.
- 사용자가 요청할 때만 접근 방향 예시를 제안하고 ‘이 방향 선택 / 수정 / 아직 탐색 중’을 제공한다. 제안 카드만 표시한 것을 사용자 선택으로 저장하지 않는다.
- 응답 중 진행 상태 표시. 실패하면 입력을 유지하고 재시도·직접 정리 제공.
- 기존 질문 중 하나를 지역 산업 접점 질문으로 교체할 수 있다. ‘선택한 분야의 어떤 일이나 이용자에게 도움이 되고 싶나요?’처럼 묻고 최대 질문 수는 늘리지 않는다. 모르면 조선·해양, 자동차, 항공, 방산, 수소·에너지, 데이터센터, AI, 2차전지 중 관심 분야를 고르거나 건너뛸 수 있다. 해당 지역과의 연결 설명은 출처가 있는 자료로 제한한다.

### 5.2 창업 구상 요약
| 항목 | 표시 |
|---|---|
| 관심과 구상 | 사용자가 설명한 하고 싶은 일 |
| 이용할 사람 | 직접 말한 대상 또는 미검증 제안 |
| 제공할 가치 | 해결할 불편이나 제공할 도움 |
| 확인할 사항 | 아직 모르는 부분과 검증이 필요한 가설 |

각 항목은 ‘직접 입력 / AI 제안·미검증 / 미정’을 표시한다. 항목별 수정과 ‘준비 안내 보기’ 제공. 요약 전체를 사업계획서 완성본으로 부르지 않는다.

요약 상단에 **‘내가 선택한 탐색 방향’**을 추가한다. 선택 문제·원문 근거·관심 이유·사용자가 고른 접근 방향·확인할 가설을 기존 카드 안에 표시한다. 방향 미선택은 ‘아직 탐색 중’으로 남긴다. AI가 사용자의 관심·의향을 대신 작성하지 않는다.

## 6. /mentor — 단계 3: 준비 안내·지역 연결

### 6.1 상단 요약
제목은 ‘나의 창업 준비 방향’. 구상 요약과 준비 상태를 간단히 보여주고 ‘내용 수정’을 제공한다. 준비도를 퍼센트나 등급으로 평가하지 않는다.

요약 아래 **‘부울경에서 시작한다면’** 카드 하나를 추가한다. 새 페이지 없이 기존 결과 영역에 배치한다.

| 카드 구역 | 내용 | 근거 구분 |
|---|---|---|
| 이 지역에서 검토할 이유 | 사용자 관심과 확인된 지역 산업·상권 배경의 접점 | 공식 배경 출처·확인일 |
| 확인할 고객·시장 | 잠재 고객 가설과 확인할 질문 | AI 제안·미검증 |
| 지역에서 준비할 경로 | 기존 지역 지원 카드로 연결 | 검수된 데이터의 실제 기관·절차 |

지역 배경은 있는데 경로가 없으면 해당 칸에 ‘확인된 이용 경로 없음’을 표시한다. 지역적 접점 자체가 약하면 ‘현재 자료로 지역 연관성을 판단하기 어려워요’로 표시한다. 창업 추천 점수·수익 전망·다른 도시보다 유리하다는 순위는 표시하지 않는다. 기존 결과에 추가 필드가 없으면 카드만 생략하고 기본 결과는 유지한다.

**결과 예시(설명용):** ‘AI + 조선·해양’ 선택 → 지역 조선·해양 배경의 출처 → 관련 업무 지원 서비스에 대한 고객 가설 → 확인할 질문 → 실제 검수된 교육·상담 경로. 예시 자체를 실제 수요나 협력 성과로 표시하지 않는다. 산업 이름만 바꾸고 동일한 사업 아이디어를 반복 추천하지 않는다.

(2026-11-27) 결과 화면은 ‘다음에 할 일’을 위에, 구상 요약(‘내가 입력한 구상 요약 보기’)은 접이식으로 아래에 둔다. 추천 목록 위에 유형 필터 칩이 있다. 관심 공고가 있으면 추천 맨 앞에 ‘관심 공고’ 표시와 함께 놓인다. 모집 중인 추천 공고마다 ‘지원서 작성’ 버튼이 있다. ‘내 조건 확인’ 팝업은 저장된 값을 유지하고 거주지는 RegionPicker 로 고른다.

### 6.2 우선 준비사항
- 우선 준비사항 1개를 먼저 보여줌.
- 구성: 제목 / 필요한 이유 / 진행 방법 / 정리할 결과.
- 후속 준비사항은 최대 2개로 제한하고 접어서 볼 수 있게 함.
- 사용자가 ‘준비 완료 표시’를 할 수 있으나 외부 상담·신청 완료와 혼동하지 않음.

### 6.3 부산에서 연결할 수 있는 지원
교육·상담·공간·지원사업 중 현재 준비에 관련 있는 최대 3개.

검수된 울산·경남 자료가 있으면 제목을 ‘선택한 지역의 준비 경로’로 표시한다. 부산 자료만 있다면 부산 안내 범위를 명시한다. 카드 순위는 준비 적합성·자격·모집 상태를 먼저 검토하고 동등한 후보에서 희망 지역을 고려한다.

| 카드 요소 | 표시 기준 |
|---|---|
| 유형·기관·제목 | 공식 자료 기준 |
| 관련 이유 | 사용자가 확인한 구상·준비 상태와 연결 |
| 이용 대상 | 거주·연령·소속·사업자 등 명시 조건 |
| 얻을 도움 | 실제 제공 범위 |
| 이용 방법 | 공식 신청/문의 경로와 필요한 준비 |
| 상태 | 모집 중·종료·상시 안내·확인 필요 |
| 근거 | 원문 링크·확인일 |

**주 버튼:** ‘공식 안내 확인’ 또는 실제 자료에 맞는 ‘신청 방법 확인’.
자격 대조가 필요하면 ‘내 조건 확인’을 눌렀을 때 관련 항목만 요청한다. 이 질문을 건너뛰어도 요약과 준비 안내는 유지한다.

### 6.4 피드백과 저장
- 질문: ‘준비 방향을 정하는 데 도움이 되었나요?’
- 선택: 도움 됨 / 아쉬움 + 선택적 이유.
- 선택적 전후 문항: ‘현재 무엇부터 준비할지 알고 있다’ 1~5점.
- 선택적 전후 지역 문항: ‘부울경을 창업 준비 지역으로 검토할 의향이 있다’ 1~5점. 선택적 결과 문항: ‘이 지역에서 준비할 경로를 찾았나요?’와 경로 이름 자유응답. 지역 의향 변화와 실제 신청·창업 성과는 구분해 집계한다.
- 요약·준비사항 복사, 기기 내 저장, 초기화.
- 계정 기능이 구현되면 결과를 본 뒤 선택적으로 가입 안내. 가입하지 않아도 결과를 읽고 복사 가능.
- 결과를 공개 링크로 자동 공유하지 않음.

## 7. 공통 예외 상태

| 상황 | 화면 처리 |
|---|---|
| 모르는 답변이 많음 | 미정 유지, 탐색·정보 확인 중심 준비 안내 |
| 적합한 지역 경로 없음 | ‘현재 확인된 자료에서 맞는 경로를 찾지 못했어요’와 준비 안내 |
| 선택 지역 자료 미확보 | 실제 제공 범위를 표시, 해당 지역 기관·수요 생성 금지 |
| 지역 변경 | 구상 요약은 보존하고 지역 검토 카드·추천 이유를 재평가 |
| 조건 미입력·원문 불명확 | 추가 확인 필요와 필요한 질문 |
| 명시 조건 불일치 | 어떤 조건이 다른지 설명, 다른 경로 보기 |
| 기간 종료 | 현재 모집 카드에서 제외, 상세 접근 시 종료 표시 |
| AI 장애 | 답변 유지·재시도·직접 정리·검수된 지역 안내 |
| 수집 장애 | 마지막 확인일 표시, 새로 확인한 것처럼 표현하지 않음 |
| 요약 수정 | 기존 결과 갱신 안내, 준비 완료 표시 초기화 안내 |
| 문제 선택 변경 | 기존 사용자 답변 보존, 지역 카드·요약·준비·추천 갱신 |
| 원하는 문제 없음 | 직접 적기·보류로 기존 대화 진행 |
| 접근 예시 전부 거절 | 탐색 중 유지, 창업 부적합으로 표시하지 않음 |

| 초기화 | 지워지는 로컬 데이터 범위 확인 후 초기화 |

‘입력 조건 부합’은 최종 자격 확인이 아니라는 설명을 조건 결과 가까이에 둔다.

## 8. 보조 화면 — P1

### /programs, /programs/:id
유형·준비 단계·키워드 중심 탐색. 상세는 초보자에게 제공하는 도움과 이용 절차를 먼저 보여주고 원문을 연결한다. 로그인이 상세 진입 조건은 아니다.
(2026-11-27) 목록 위쪽에 정렬 select(나에게 맞는 순·최근 공모·많이 본 공모·마감 임박)와 지역 선택(RegionPicker: 전체/부산/울산/경남 → 구·군·시·군 칩)이 있다. 구·군은 공고 글에서 글자로 맞추고, 지역 전체 대상 공고에는 ‘○○ 전역’ 표시가 붙는다. 한 페이지 10건, 페이지 번호는 5개 창이다. 마감 7일 이내 공고에는 ‘D-n’, 마감 당일에는 ‘오늘 마감’ 배지가 붙는다. 상세에는 ‘내 구상에 맞는 준비 안내 받기’ 링크가 있어 `/mentor?focus=<id>` 로 간다.
모집 상태 배지는 모집 중·마감·상시·마감일 미정이다. 조건 배지는 조건 맞음·확인 필요·조건 다름이다. 배지는 글자를 함께 보여 준다.

### /programs/:id 지원서 작성
모집 중인 공고에서 로그인한 사용자가 ‘지원서 작성’으로 초안을 만든다. 백엔드가 공고 양식을 읽고(Upstage Document Parse, DocWorker 컨테이너, URL별 캐시) Solar 가 신원 정보가 아닌 칸의 초안을 쓴다. 로그인하지 않았으면 로그인으로 보낸다. 이메일 인증을 마치지 않은 계정은 만들 수 없다 (403 `email_unverified`). 지원서 작성은 계정당 7일에 2회까지이며, 넘으면 다시 쓸 수 있는 날짜를 알려 준다 (429 `application_limit`).

### /applications/:id
지원서 화면. 로그인 필요. 순서는 수정 → 제출 전 확인 → 작성 완료다. AI 초안 칸은 사용자가 확인하게 표시한다. ‘AI로 다듬기’(지원서당 5회, 남은 횟수 표시)는 칸마다 다듬은 글을 보여 주고 ‘이 글로 바꾸기’·‘그대로 두기’를 고르게 한다. 바꾼 글은 ‘임시 저장’을 눌러야 저장된다. ‘지원서 파일 내려받기’에서 워드(DOCX)·파워포인트(PPTX)·한글(HWPX)을 같은 내용으로 받는다. 공고에 공식 양식(DOCX·HWPX·PPTX)이 있으면 그 양식에 채우고, 없으면 공문 형식의 공통 양식으로 만든다. ‘내가 찾은 제출 양식에 채우기’로 사용자가 받은 양식(DOCX·HWPX·PPTX)을 올리면 채워서 돌려준다. PDF 는 ‘PDF로 저장’(브라우저 인쇄 창)으로 받는다. HWP 가 필요하면 한글에서 HWPX 를 열어 저장하라고 안내한다. 작성 완료 후 ‘공식 안내에서 신청하기’ 링크를 보여 준다. 해보까는 대신 제출하지 않고 공식 사이트에서 직접 신청한다고 화면에 적는다. 화면에는 영수증 번호를 보이지 않는다. API 는 `/api/applications` (`packages/shared/src/api.ts`).

### /guide
이용 방법. 처음 창업을 알아보는 사람을 위해 AI 상담 순서와 각 페이지의 쓰임새를 짧게 설명한다.
정렬 버튼: 나에게 맞는 순·최근 공모·많이 본 공모·마감 임박. 카드와 상세 오른쪽 위에 하트(관심 표시, 44px 터치 영역, aria-pressed). 비로그인 사용자가 누르면 로그인으로 보낸다. 나에게 맞는 순에서는 '하트 누른 공고에서 읽은 관심'을 한 줄로 보여 준다. 상세의 '대상과 조건'에 내 정보와 비교한 항목별 결과를 보여 준다.

### /signup
이메일, 비밀번호, 비밀번호 확인, 개인정보 안내 동의. 입력하는 동안 '두 비밀번호가 같아요/달라요', 규칙(8~64자, 영문·숫자 포함) 충족 여부를 글자로 보여준다. 가입 후 '인증 메일을 보냈어요' 화면(받은 메일의 링크 또는 6자리 코드 입력, 다시 보내기).

### /verify
메일 링크로 들어오면 자동 인증, 또는 코드 입력. 성공하면 로그인 상태로 창업 준비로 이동.

### /login, /forgot
로그인 아래 '비밀번호 찾기'(/forgot): 이메일 입력 → '가입된 이메일이면 복구 비밀번호를 보냈어요'(계정 존재를 드러내지 않음). 복구 비밀번호로 로그인하면 새 비밀번호 설정 화면으로 보낸다. 인증하지 않은 계정은 로그인 후 인증 안내.

### /me
내 정보. 계정 이메일, 기본 정보, 이번 주 상담 횟수, 비밀번호 변경(현재 비밀번호 + 새 비밀번호 2회), 창업 유형 테스트 결과, 내 지원서 목록, 로그아웃, 계정 삭제.

### /bufs (관리자)
관리자 비밀번호 입력 → 의견 목록과 요약(도움 됨 비율, 방향 정리 비율, 지역 경로 발견 비율, 지역 검토 의향 전후 평균). 일반 메뉴에 노출하지 않는다. 로그아웃 버튼.

### /me 기본 정보
나이(만), 거주지(RegionPicker: 부산 구·군, 울산 구·군, 경남 시·군, 그 밖의 지역), 사업자 여부, 현재 직군(고등학생·대학생·대학원생·직장인·프리랜서·자영업·구직 중·기타). 모두 선택, '모름' 가능. 저장하면 '내 조건 확인'에 기본값으로 채운다.

### /test
창업 유형 테스트: 시작 → 12문항(한 화면에 한 문항, 진행 막대, 이전) → 결과(유형·한 줄 설명·축별 막대·강점·주의할 점, '재미·참고용이며 자격 판정에 쓰지 않아요' 표시, '이 유형으로 창업 준비 시작', 다시 하기). 메뉴에 노출하되 메인 핵심 약속으로 소개하지 않는다.

### /admin
팀 통계(F14). 로그인한 팀 계정만 집계 지표를 볼 수 있다. 메뉴에는 링크가 없다. 원문 대화·신원 정보는 통계 화면에 표시하지 않는다. 세션/기기 단위와 대상 사용자 인터뷰 수를 구분한다.

### /licenses
사용한 오픈소스의 라이선스 고지.

## 9. 피그마·개발 인계 기준

필수 시안은 3개 묶음: 메인, 탐색·대화, 결과. 각 묶음에 아이디어 없음·건너뛰기·오류·빈 결과 상태를 포함한다.

- 프론트는 공고 추천보다 구상 정리와 준비 안내를 결과 상단에 배치한다.
- AI·데이터 담당자는 사실/가설, 조건 상태, 모집 상태를 구분한 출력을 합의한다.
- 기획 담당자는 지역 경로의 공식 출처·이용 절차를 검수한다.
- 화면 완료 기준은 예쁜 정적 시안이 아니라 비회원으로 시작부터 결과·수정까지 진행되는 것이다.

## 10. 시연 흐름과 팀 피드백

시연: 관심 또는 막연한 구상 입력 → 쉬운 질문 → 구상 요약 → 수정 → 준비사항 → 출처 있는 부산 경로.
시연 인물의 경험·매출·의향을 실제 사용자 조사처럼 제시하지 않는다.

팀 검토:
- [ ] 첫 화면에서 제공 가치를 설명할 수 있는가?
- [ ] 모르는 항목 때문에 진행이 막히지 않는가?
- [ ] 결과가 지원금 신청을 무조건 권하지 않는가?
- [ ] 지역 카드의 정보가 실제 공식 자료와 일치하는가?
- [ ] 기존 개발 화면 중 재사용·후순위 전환할 부분이 합의됐는가?

## 11. 팀 적용 순서: 이번 추가분만 반영할 경우

| 순서 | 수정 위치 | 필수 변경 | 완료 확인 |
|---|---|---|---|
| 1 | 기존 입력 폼·대화 상태 | 선택적 창업 검토 지역 | 미정·다른 거주지에서도 진행 |
| 2 | 기존 AI 질문 | 지역 접점 질문 하나와 검수 자료 전달 | 질문 수 유지·추정 경험 생성 없음 |
| 3 | 기존 요약 결과 | 지역 검토 선택 필드와 카드 하나 | 공식 사실·고객 가설·경로 구분 |
| 4 | 기존 추천 카드 | 단계별 이유와 실제 이용 절차 | 검토 지역으로 자격을 대체하지 않음 |
| 5 | 기존 설문 | 선택적 지역 검토 의향·경로 이해 문항 | 무응답 허용·클릭과 성과 구분 |

전체 UI 개편·회원 시스템 변경·기존 제출 기능 삭제를 이 추가분의 선행조건으로 삼지 않는다. 기존 PR의 접근성 개정안과 이번 지역성 보완 중 적용 범위를 팀이 각각 검토할 수 있다. 이번 변경은 문서 명세이며 실제 UI·추천·지역 데이터 구현 완료를 의미하지 않는다.

## 12. 추가 화면 변경: 지역 문제를 보고 직접 탐색 방향 선택

> (2026-11-27) 아래 12.1의 문제 카드 묶음 ‘어떤 문제를 더 알아보고 싶나요?’는 상담 화면에서 뺐다 (#100). 직접 적기 입력은 남아 있다. 이 절은 당시 기획으로 남긴다.

### 12.1 기존 입력 화면 또는 첫 대화 영역에 카드 묶음 추가

제목: **‘어떤 문제를 더 알아보고 싶나요?’**
설명: ‘관심 있는 지역 문제를 선택해 창업 방향을 살펴보세요. 직접 생각한 문제로 시작해도 됩니다.’

관심 분야·지역에 맞는 검수 카드를 최대 3개 보여준다. 새 페이지·지도·기업 접수 화면은 만들지 않는다.

| 카드 요소 | 화면 내용 |
|---|---|
| 제목·산업·지역 | 근거 자료와 연결된 문제 설명 |
| 대상·상황 | 누가 언제 어떤 어려움을 겪는지 |
| 기존 방식 | 확인된 처리 방식, 없으면 미확인 |
| 근거 | 인터뷰에서 확인 / 기사·공식 자료에 보고 / 조사 후보 |
| 출처·시점 | 원문 또는 공개 가능한 기록, 자료 시점·검수일 |
| 미확인 사항 | 현재 지속 여부·구매 의향·해결책 등 별도 확인 내용 |
| 행동 | ‘이 문제 탐색하기’, ‘근거 보기’ |

아래에 ‘직접 적기 / 다른 문제 보기 / 아직 탐색 중’을 제공한다. 하나를 골라도 다시 바꿀 수 있다. 데이터가 없는 분야는 ‘현재 확인된 문제 자료가 없습니다’와 직접 입력 경로를 보여준다. 예시·조사 후보는 검증된 현장 문제와 구분하며 AI 생성 사실로 빈칸을 채우지 않는다.

### 12.2 기존 대화·결과 재사용

문제 선택 → 관심 이유·경험 질문 → 접근 방향 입력(원할 때 예시 도움) → 사용자 확인 → 기존 구상 요약·지역 검토 카드·준비사항·지원 추천.

주요 결과 제목은 ‘당신에게 맞는 창업’ 대신 ‘내가 선택한 탐색 방향’. 방향을 정하지 않아도 준비 안내를 볼 수 있다. 기존 산업 8개 선택은 유지하되 모든 분야의 문제 카드 확보를 출시 조건으로 만들지 않는다.

### 12.3 개발 적용과 수용 기준

| 담당 | 최소 변경 | 확인할 동작 |
|---|---|---|
| 기획·데이터 | 분야 하나의 근거 있는 카드 2~3개 준비 | 자료 유형·시점·한계 구분 |
| 프론트 | 기존 화면 카드 묶음·선택 상태·직접 입력 경로 | 선택·변경·보류 가능 |
| AI | 선택 문제와 관심 이유를 대화 입력에 전달 | 문제·접근 방향을 대신 확정하지 않음 |
| 결과·추천 | 기존 카드에 선택 방향 표시·입력 재사용 | 변경 후 예전 문제 근거·추천 잔존 없음 |
| 검증 | 자기주도 탐색 피드백 추가 | 사용자가 선택 이유와 확인할 내용을 설명 |

문서만 바뀐 상태와 실제 구현 상태를 구분한다. 자료가 없으면 기존 대화로 동작하고, 팀 검수 전 사례를 확보된 고객 수요로 발표하지 않는다.

## 13. 선택 보완과 확장안: 현장 확인

### 13.1 이번 결과 화면에서 여력 있을 때 추가(P1)

기존 준비사항 아래에 접이식 **‘현장에 확인할 질문’** 영역을 둔다. 사용자가 펼치면 선택 문제·미확인 가설과 연결된 질문 최대 3개, 질문 의도, 편집·복사 버튼을 보여준다. ‘현장 확인 전’ 상태를 표시한다.

이 영역은 기존 결과의 보조 항목이며 모달·새 페이지·외부 전송 버튼이 필수는 아니다. 아직 구현되지 않았다면 작동하지 않는 검토 요청 버튼을 노출하지 않는다.

### 13.2 향후 확장(P2)

실제 현장 참여자를 확보하고 운영 방식을 합의한 후 ‘구상·질문 검토 → 피드백 요청 → 실제 응답 → 사용자 구상 수정’을 연결한다. 현재 시연의 필수 화면으로 그리지 않는다. 소개한다면 ‘확장 계획’임을 명시한다.

참여자가 있는 수동 시범 사례는 ‘질문 준비 / 현장 확인 전 / 실제 응답 받음 / 구상 수정’ 상태와 답변 시점·범위를 기록한다. 응답하지 않은 상태를 긍정 평가로 바꾸지 않는다. 답변자의 공개 동의 없이 이름·연락처·비공개 업무 내용을 화면에 표시하지 않는다.
