> 팀 피드백용 수정안. 상위 문서: [prd.md](prd.md). 화면: [web-pages.md](web-pages.md).

## 2. 시작과 대화

### F1. 준비 상태·관심 입력 및 지역 문제 선택

**입력**
- 준비 상태: ‘관심은 있지만 아이디어가 없어요 / 생각해둔 아이디어가 있어요 / 구체적으로 준비 중이에요’.
- 아이디어 있음: 해보고 싶은 일 200자 이내.
- 아이디어 없음: 관심 분야 또는 자신의 경험 1개 이상 선택·입력. ‘직접 적기’ 허용.
- 산업 선택 예시: 조선·해양 / 자동차 / 항공 / 방산 / 수소·에너지 / 데이터센터 / AI / 2차전지. ‘아직 모름 / 기타’ 포함. 기존 관심 분야 UI를 재사용하고 별도 페이지는 추가하지 않는다.
- 산업과 AI의 복수 선택을 허용한다. 선택 UI가 단일 선택으로 구현돼 있다면 추가 접점은 대화에서 확인할 수 있으며, 전체 입력 구조 재개편을 선행조건으로 삼지 않는다.
- 지역 (2026-11-27 변경): 활동 지역과 검토 지역을 하나의 칸으로 합쳤다. 지역 선택(RegionPicker)에서 부산 / 울산 / 경남과 구·군·시·군을 고르거나 ‘미정’을 고른다. 지원 거주요건과 같은 값으로 취급하지 않는다. 미정이어도 진행한다. 실제 데이터 지원 범위를 함께 표시한다.
- 관심 공고 (2026-11-27): 공고 상세의 ‘내 구상에 맞는 준비 안내 받기’로 `/mentor?focus=<id>` 에 들어오면 시작 정보 `focusResourceId` 에 그 공고를 저장한다. 상담 시작 화면에 ‘관심 공고’ 배너가 보이고 ‘관심 공고 빼기’로 지울 수 있다 (null 저장).
- (2026-11-27 변경: 아래 문제 카드 블록 ‘어떤 문제를 더 알아보고 싶나요?’는 상담 화면에서 뺐다. 문제를 직접 적는 입력은 남아 있다.)
- 관심·지역에 연결되는 F21 문제 카드 최대 3개를 기존 화면에 표시한다. 출처·근거 수준·미확인 사항을 열람하고 하나를 선택한다. 직접 입력·탐색 보류도 제공한다.
- 문제 ID와 자료 버전 또는 확인 시점, 사용자 선택 이유(선택 입력)를 저장한다. AI 자동 선택을 사용자 결정으로 기록하지 않는다.

**규칙**
- 처음부터 업종 코드·B2B·수익 구조·사업자 개업일을 요구하지 않는다.
- 아무 입력도 없는 경우에만 선택을 안내한다. 긴 설명을 강요하지 않는다.
- 관심 분야를 선택했다고 창업 업종을 확정하지 않는다.
- 기존 사업자 이용자는 준비 중 경로로 이동하되 전문 경영 자문은 제공 범위가 아님을 안내한다.

**완료 기준:** 문제 선택·직접 입력·보류 모두 기존 F2로 진입한다. 카드가 없거나 참조가 만료돼도 진행을 막지 않고 상태를 알린다.

### F2. 쉬운 질문 기반 창업 탐색

**입력:** F1과 현재 대화.
선택 문제의 검수 요약과 근거 수준도 전달한다. 사용자 작성 문제는 외부 검증 자료와 구분한다.
**출력:** 한 번에 질문 하나, 예시 또는 선택지, ‘아직 모르겠어요’, ‘건너뛰기’.
**질문 범위:** 기본 최대 3개. 충분히 답했다면 일찍 정리할 수 있다. 3개 후 임의의 추가 질문으로 결과 진입을 막지 않는다. 요약 화면의 ‘AI와 더 이야기하기’(`POST /api/explore/chat` `{more:true}`)를 누르면 같은 상담에서 후속 질문(9개 중 순서대로)을 이어 받는다. 한 상담은 최대 12문항이다. 응답에 `quota`와 `maxQuestions`가 들어 있다.
**관심 공고·지역 질문 (2026-11-28):** 관심 공고로 시작하면 첫 질문이 ‘‘○○’ 공고를 보고 오셨네요. 이 지원을 받는다면 무엇부터 해 보고 싶으세요?’다. 지역 질문은 고른 지역·구·군과 지역 산업에 맞춰 바뀐다.
**질문 문장 (2026-11-27):** 질문은 규칙 원문을 그대로 쓴다. AI(Solar Mini)는 직전 답을 받아 주는 반응 한 문장만 앞에 붙인다 (질문·조언·평가 금지, 사용자 말 되풀이 금지, 말끝을 바꾼다, 40자 안팎, 검사 상한 60자). 검사에 걸리면 반응 없이 규칙 질문만. 평가에서 AI 가 질문을 다시 쓰면 11건 중 6건의 뜻이 바뀌었다 (`docs/ai-eval.md`).

| 알아볼 내용 | 사용자에게 제시할 표현 예시 |
|---|---|
| 관심의 계기 | 이 일을 해보고 싶어진 경험이 있나요? |
| 문제 선택 이유 | 이 문제의 어떤 부분이 관심을 끌었나요? |
| 자신의 접점 | 관련해 겪거나 알고 있는 경험이 있나요? 없어도 괜찮아요. |
| 접근 방향 | 이 문제에서 더 알아보고 싶은 부분이나 도움이 될 수 있다고 생각하는 점이 있나요? |
| 도움받을 사람 | 어떤 사람이 이용하면 좋을까요? 아직 정하지 않아도 괜찮아요. |
| 준비 상태 | 지금까지 알아보거나 준비한 것이 있나요? |
| 지역 접점 | 부울경의 조선·해양, 자동차, 항공, 방산, 수소·에너지, 데이터센터, AI, 2차전지 분야 중 이 구상과 연결해보고 싶은 분야가 있나요? |
| 관심만 있는 경우 | 선택한 산업에서 제품을 만드는 일과 관련 업무를 돕는 서비스 중 살펴보고 싶은 방향이 있나요? |

**규칙**
- 질문은 면접·심사처럼 채점하지 않는다. 과도한 칭찬이나 성공 가능성 평가를 하지 않는다.
- AI가 사업 아이템을 먼저 확정하지 않는다. 사용자가 예시·도움을 요청한 경우에만 접근 방향을 최대 2개 제안한다. 선택·수정·모두 보류를 허용한다.
- 사용자가 모르는 항목은 미정으로 저장한다. 추정으로 채우지 않는다.
- 사용자에게 없는 고객 인터뷰·매출·팀·경험을 만들지 않는다.
- 기관·금액·마감일은 검수 데이터에서만 제시한다.
- 동일 응답 재전송과 중복 결과 생성을 막는다.
- 지역 접점 질문은 기존 질문 중 하나를 대체하며 기본 최대 3개 제한을 늘리지 않는다. 이미 답한 경우 반복하지 않는다.
- 지역 접점을 모르면 카드 근거를 설명하고 다른 문제 보기·직접 탐색을 제공한다. 방향 예시는 사용자가 원할 때만 제안한다.
- 관심 산업을 적성으로, 문제 선택을 해결책 채택으로 해석하지 않는다. 선택한 문제를 바꾸려면 먼저 사용자 의사를 확인한다.

**완료 기준:** 아이디어 있음·없음·모든 질문 건너뛰기에서 모두 결과로 갈 수 있다. 장애 시 재시도와 수동 정리 양식이 보인다.

### F3. 사용자 선택 기반 탐색 방향·창업 구상 요약

**출력 항목**
1. 관심 분야와 하고 싶은 일.
2. 도움을 주고 싶은 대상.
3. 해결해보고 싶은 불편 또는 제공할 가치.
4. 아직 확인하지 않은 사항.

**자기주도 탐색 항목:** 선택한 문제와 출처 / 사용자가 말한 관심 이유 / 직접 선택·수정한 접근 방향 / 확인할 고객·시장 가설. 기존 요약 영역에 추가하며 별도 페이지는 만들지 않는다. 방향 미선택은 ‘아직 탐색 중’, 직접 입력 문제는 ‘사용자 작성·외부 검증 전’으로 표시한다.

각 항목에 ‘직접 입력 / AI 제안·미검증 / 미정’을 표시한다. 편집했다고 실제 검증된 사실이 되는 것은 아니다. 수익 구조와 지역 연계는 근거가 없으면 필수로 생성하지 않는다.

**수정 규칙:** 수정 내용이 추천·준비 안내에 반영된다. 기존 준비사항 체크는 재생성 전에 사용자에게 알리고 초기화한다.
문제 변경 시 기존 사용자 입력을 보존하고 현재 문제 ID를 갱신한다. 대화·요약·추천을 새 선택에 따라 재평가하며 이전 문제의 사실을 새 근거로 사용하지 않는다.

**완료 기준:** 원래 입력이 요약에서 유지되고 AI 제안은 구분된다. 수정 후 결과가 갱신된다.

**결과 화면 (2026-11-27 변경):** 결과 위쪽에 ‘다음에 할 일’을 둔다. 구상 요약은 조용한 접이식(‘내가 입력한 구상 요약 보기’)으로 아래에 둔다. 추천 목록에는 유형 필터 칩이 있다. ‘내 조건 확인’ 팝업은 저장된 값(내 정보·대화 입력)을 그대로 보여 준다 (값이 지워지던 오류 수정).

**지역 검토 카드 추가:** 기존 요약 아래 카드 1개를 붙인다. 새 요약 페이지는 만들지 않는다.
- 지역에서 검토할 이유: 지역 배경의 사실·원문과 사용자 관심의 연결을 분리해 설명한다.
- 확인할 고객·시장 가설: 구매 의향이나 현장 수요가 확인된 것처럼 서술하지 않는다.
- 지역에서 준비할 경로: F21의 검수된 경로 ID를 연결한다. 없으면 미확인으로 둔다.
- 결과 상태: 검토할 근거 있음 / 추가 확인 필요 / 현재 자료로 연결 어려움. 사업 성공·지역 우위 점수가 아니다.
- 지역·구상을 수정하면 카드와 추천을 함께 갱신한다.

## 3. 준비 안내와 지역 연결

### F12. 우선 준비사항과 후속 준비 안내

**입력:** 사용자가 확인한 요약과 현재 준비 상태.
접근 방향이 정해지면 그 방향의 가설을 확인할 준비를 안내한다. 미정이면 문제의 이용자·발생 상황을 알아보는 준비를 제시하며 해결책을 강요하지 않는다.
**출력:** 우선 준비사항 1개, 후속 준비사항 최대 2개.

각 항목은 ‘무엇을 준비할지 / 지금 필요한 이유 / 진행 방법 / 준비 결과로 남길 것’을 포함한다.

지역 접점이 확인되면 그 고객 가설을 확인할 질문이나 실제 지역 교육·상담 이용 준비를 포함한다. 문의할 기관의 실제 운영 범위와 연결하며 상담 예약·기업 응답·협력 성사를 보장하지 않는다.

예: 고객이 미정이면 ‘이용할 사람의 상황 구체화’를 우선으로 제시한다. 구상이 정리되고 학습이 필요하면 실제 입문 교육을 안내한다. 일정 기간 계획이나 공고 신청을 모든 사람에게 일률적으로 부여하지 않는다.

**규칙**
- 자금 지출·사업자등록·지원금 신청을 기본 첫 단계로 권하지 않는다.
- 검증 전 수익성과 시장 수요를 확정하지 않는다.
- 체크는 ‘준비 완료 표시’이며 실제 수행의 객관적 증거로 취급하지 않는다.

**완료 기준:** 요약이 미정이어도 안내가 나오며, 다른 준비 상태에 동일한 계획을 반복하지 않는다.

#### F12 선택 보완 — 현장 확인 질문(P1)

- 입력: 선택 문제·사용자가 확인한 구상·현재 미확인 가설.
- 출력: 확인할 질문 최대 3개와 질문별 확인 목적. 사용자가 수정하고 복사할 수 있다.
- 질문 예: ‘이 업무는 현재 어떤 방식으로 처리하나요?’, ‘어느 단계에서 시간이 많이 드나요?’, ‘외부 서비스를 검토하기 전에 어떤 조건을 확인하나요?’
- 예시는 일반적인 질문 형식이다. 응답자의 어려움이나 구매 의향을 전제하지 않고 현재 방식과 실제 경험을 먼저 묻는다.
- 상태는 ‘현장 확인 전’으로 표시한다. AI가 응답자·답변·검증 결과를 생성하지 않는다.
- 담당: AI·프론트·기획. 없어도 P0 결과·준비 안내는 동작한다. 별도 기능 ID·페이지·발송 API를 추가하지 않는다.
- 완료 기준: 선택 문제와 질문이 연결되고 수정·복사가 가능하다. 문제 변경 시 질문도 재평가한다.

#### 향후 확장 — 실제 피드백 연결(P2)

참여에 동의한 지역 사업자·현장 경험자에게 사용자가 검토한 구상과 질문을 전달하고, 실제 답변을 보고 사용자가 방향을 수정하도록 연결한다. 이번 범위에서는 요청 자동 발송·매칭·예약·채팅을 구현하지 않는다.

담당자가 수동 시범 검증을 진행한다면 동의·전달할 내용·답변 공개 범위·답변 시점·확인한 사실·남은 가설을 구분한다. 요청 전/요청 후 미응답/실제 응답/구상 수정은 다른 상태로 취급한다. 실제 응답을 AI가 보완·위조하지 않는다. 부정적 답변이나 방향 보류도 결과로 인정한다.

### F21. 검수된 지역 문제·맥락·지원 데이터

목표 범위는 부울경이며 실제 제공 범위는 검수 데이터가 있는 지역·분야로 제한한다. 아래 명세는 기존 부산 데이터를 삭제하거나 울산·경남의 전체 자료 수집을 요구하지 않는다.

데이터는 교육·상담·공간·지원사업을 구분한다. 첫 배포는 5~10개를 목표로 하되 확보 수와 미확인 항목을 정직하게 기록한다.

**필드:** ID, 유형, 제목, 기관, 공식 URL, 대상, 준비 단계, 내용, 신청·문의 절차, 사전 준비, 이용 가능 지역, 소속 제한, 기간·비용, 모집 상태, 확인일, 원문 근거.

**최소 확장 필드:** 지역, 분야 태그, 제공 역량 태그(교육·상담·시제품 등), 관련 지역 맥락 ID. 명시 근거 없는 태그는 미확인으로 둔다.

**산업 태그 기준:** 조선·해양, 자동차, 항공, 방산, 수소·에너지, 데이터센터, AI, 2차전지. UI와 추천 데이터에서 같은 명칭을 사용한다. AI·2차전지를 하나의 태그로 묶지 않는다. AI는 산업 간 적용 태그로도 사용할 수 있다. 사용자의 관심 태그와 기관이 실제 지원하는 분야 태그를 구분하며, 관심 태그만으로 기관 역량·프로그램 자격을 추정하지 않는다.

산업별 지역 맥락 자료가 없으면 해당 분야 배경·지원 경로는 확인 필요로 둔다. 데이터센터·방산 등 선택지가 있다는 이유만으로 현재 창업 지원이나 입주·협력 기회가 있다고 표시하지 않는다.

**지역 맥락 자료:** 기존 JSON 또는 테이블에 별도 목록으로 ID, 지역, 분야, 확인된 배경 설명, 공식 URL, 근거 문구, 확인일을 저장한다. 경로 데이터와 ID로 연결한다. 별도 추천 서버·벡터 DB·자동 크롤러는 필수가 아니다.

산업 기반이 존재한다는 자료를 창업 수요·계약 가능성의 증거로 재사용하지 않는다. 검토용 사업 방향은 AI 가설로 분리한다.

**지역 문제 카드:** 기존 JSON/테이블에 소수 자료를 추가하며 접수 플랫폼·자동 수집기는 만들지 않는다.

| 필드 | 내용 |
|---|---|
| id, region, industry_tags | 식별자·지역·기존 산업 태그 |
| title, affected_user, situation | 제목·대상·발생 상황 |
| current_workaround | 기존 처리 방식, 모르면 미확인 |
| source_type, source_ref, source_excerpt | 인터뷰/기사/공식 자료/조사 후보, 공개 가능한 원문 또는 기록 ID, 근거 요약 |
| evidence_level | 인터뷰에서 확인 / 기사·공식 자료에 보고 / 조사 후보 |
| source_date, checked_at, current_status | 자료 시점·검수일·현 상태 확인/미확인 |
| unknowns, context_ids, resource_ids | 미확인 사항·지역 맥락·지원 경로 참조 |

- 문제 사실과 해결책·지불 의향 가설을 구분한다. 조사 후보를 확인된 현장 문제로 표시하지 않는다.
- 기사 보도 이후의 상태·기존 서비스는 별도 확인하며 과거 보도를 현재 수요로 단정하지 않는다.
- 인터뷰 공개 동의·익명화 범위를 확인하고 비공개 원문을 결과나 로그에 노출하지 않는다.
- 첫 구현은 분야 하나의 검수 카드 2~3개가 목표다. 자료가 없으면 빈 상태와 직접 입력을 제공한다.

- 누락은 ‘확인 필요’, 무료 여부가 없으면 비용을 추정하지 않는다.
- 기관 상시 안내와 기간 한정 사업을 구분한다.
- 과거 안내책자를 현재 모집 중인 프로그램의 증거로 사용하지 않는다.
- 자료 충돌 시 추천을 보류하고 공식 문의 경로를 제공한다.

**완료 기준:** 표시하는 각 데이터에 공식 링크·확인일이 있고, 기획 담당자가 대상·기간·이용 절차를 검수했다.

### F4. 조건 대조

지원 상세 확인에 필요한 경우에만 나이·거주지·소속·사업자 여부를 묻는다. ‘모름/입력하지 않음’을 허용한다.

**출력:** ‘입력 조건 부합 / 추가 확인 필요 / 명시 조건 불일치’와 항목별 근거.
- 입력 조건 부합은 수집·검수한 조건 범위에서의 비교이며 최종 신청 자격 보장이 아니다.
- 사용자 정보·원문 조건이 없거나 일부 조건을 확인하지 못하면 추가 확인 필요. 원문 조건이 없어도 입력한 값은 문구에 보여 준다 (예: '입력한 나이는 25세예요. 원문에 나이 조건이 없어…').
- 원문에 '나이 제한 없음'(모든 나이를 빈틈 없이 나열한 경우 포함)이면 부합. 원문 거주 조건이 없으면 지원 지역과 비교한다: 전국은 부합, 지원 지역 안이면 부합(사업장 소재지 조건은 확인 안내), 다른 지역이면 불일치가 아니라 추가 확인 필요.
- 명시 조건 불일치와 다른 준비 단계의 추천은 구분한다.
- 자격 판단을 AI의 유사도 점수로 대신하지 않는다.
- 상시 모집은 명시 근거가 있을 때만 상시로 취급한다.

**완료 기준:** 미입력·모호한 원문·나이 경계·마감 당일/종료 사례의 기대 결과가 확인된다.

### F5. 단계별 지역 지원 추천 / F6. 이유

검수 데이터 중 준비 단계·목적·이용 조건을 기준으로 최대 3개를 제시한다. 기관·교육·지원금 중 사용자 상황에 맞는 유형을 선택하며 개수나 마감 임박 여부를 위해 부적절한 자료를 채우지 않는다.
선택 문제와 사용자가 확인한 접근 방향을 추천 입력으로 재사용한다. 산업 태그만으로 기관 역량을 추정하지 않으며 방향 변경 시 추천과 이유를 함께 갱신한다.

**순위 (2026-11-27):** 규칙이 후보를 거르고(명시 조건 불일치·모집 종료·준비 단계, 최대 26건) Solar Decide 가 관련도 순으로 고른다. 입력은 대화·요약·접근 방향·내 정보·하트 관심. 관련도가 1위의 20% 미만이면 넣지 않는다. Decide 가 꺼져 있거나 실패하면 아래 규칙 순위를 쓴다. 결과 화면에 순위 기준('AI 관련도 순' 또는 규칙)을 표시한다.

**관심 공고·최근 본 공고 (2026-11-27):** 시작 정보에 관심 공고가 있으면 AI 맥락에 그 공고, 하트, 사용자가 최근 본 공고 10개(`recent_views`)를 함께 넘긴다. AI를 끈 경우 첫 질문이 관심 공고에 대한 질문이 된다. 결과에서는 관심 공고를 맨 앞에 두고 ‘관심 공고’ 표시를 붙인다. 최근 본 공고는 하트의 절반으로 센다. 결과의 모집 중인 추천 공고마다 ‘지원서 작성’을 제공한다 (F13).

**지역 우선 규칙:** 먼저 명시된 조건 불일치·모집 종료를 제외하고 준비 단계·필요 역량을 맞춘다. 동등하게 적합한 후보에서 사용자 검토 지역과 연결되는 경로를 우선한다. 사용자 희망 지역이 신청 자격을 대신하지 않는다. 전국 대상 자료도 실제 대상에 맞으면 제시할 수 있다.

이유에는 ‘이 지역이라서’만 쓰지 않고 ‘구상의 어떤 준비를 지원하는지’를 설명한다. 적합한 후보가 없는 지역을 채우기 위해 다른 기관의 역량을 지어내지 않는다.

**카드:** 유형, 제목, 기관, 현재 단계와 연결되는 이유, 얻을 도움, 이용 절차, 조건 상태, 모집 상태, 원문, 확인일.
- ‘유사도’를 ‘선정 확률’로 표시하지 않는다.
- 맞는 결과가 없으면 명시하고 F12 준비 안내를 유지한다.
- 이유는 사용자 확인 내용과 원문에 근거한다.
- AI 장애 시 검수 데이터와 규칙 기반 설명을 제공한다.

**완료 기준:** 미정 사용자·적합 자료 없음·일부 조건 미확인·마감된 자료에서 오해 없이 결과가 나온다.

### F11. 기관과 이용 경로

기관명·주소만 제시하지 않고 어떤 도움을 요청할 수 있는지, 대상, 공식 문의/신청 경로, 준비할 내용을 보여준다. 실제 상담 가능 여부를 데이터 없이 확정하지 않는다. 대학 기관은 재학생·졸업생·외부인 조건을 구분한다.

### F7. 모집 상태 관리 / F8. 자동 갱신

F7은 P0. 한국 시간으로 기간과 접수 상태를 확인하고 종료된 프로그램을 현재 모집 중 추천에서 제외한다. 마감일만 있고 시각이 없으면 정확한 종료 시각을 확인하도록 표시한다. 상시 기관 안내는 기간 한정 프로그램과 별도로 보여준다.

F8은 P0 (2026-11-27 변경). 공식 지원사업은 공공데이터포털 「창업진흥원_K-Startup 조회서비스」 `getAnnouncementInformation02` 의 실제 응답으로 채운다. 매일 새벽(한국 시간)과 운영자가 요청할 때 부산·전국 모집 중 공고를 받아 `pbanc_sn` 기준으로 추가·갱신한다. 원문 링크(`detl_pg_url`), 접수 기간, 대상, 연령, 창업 연차를 그대로 보여주고 확인일은 수집 시각이다. 실패하면 마지막 수집 자료와 확인일로 동작하며 오래된 자료를 최신으로 표시하지 않는다. API 키는 서버 secret 으로만 둔다. 교육·상담·공간 경로(F21)는 계속 팀 검수 자료다. 메인의 모집 중 건수와 마감 임박 공고도 같은 수집 공고로 계산한다 (2026-11-28).

## 4. 저장·검증·보조 기능

### F9. 계정·기기 저장·초기화 — P0
- 진행 상태는 로그인한 계정에 저장한다. 같은 내용을 현재 기기에도 저장해 새로고침·일시적 연결 끊김에서 바로 복구한다 (시작 정보·선택 문제·대화·요약·결과·준비 완료 표시·현장 질문·피드백 초안).
- 현재 기기에 진행 상태와 요약을 저장해 새로고침 시 복구한다.
- 기기·브라우저가 바뀌면 이어지지 않는다는 안내를 제공한다.
- 초기화하면 로컬 상태를 지운다. 진행 중 서버에 전달된 데이터와 로그의 보관 범위는 별도로 명시한다.
- 원문 대화가 담긴 결과를 자동 공개 링크로 만들지 않는다.

### F10. 피드백 — P0
- 결과 후 유용/아쉬움과 선택적 이유를 받는다.
- 선택 문항 ‘내가 더 알아보고 싶은 창업 방향을 정리할 수 있었다’와 ‘선택한 문제에서 어떤 부분을 더 알아보고 싶나요?’를 제공한다. 선택·변경은 탐색 이벤트로만 기록하고 구매 수요로 해석하지 않는다.
- 사용 전후 동일한 준비 방향 이해도 문항을 선택적으로 제공한다.
- 선택적 지역 문항: ‘부울경을 창업 준비 지역으로 검토할 의향이 있다’ 1~5점(전후 동일), ‘결과에서 알게 된 지역 준비 경로가 있나요?’와 선택적 자유응답. 부정 응답·무응답을 허용한다.
- 지역 경로 펼치기·공식 링크 이동을 기존 이벤트에 추가할 수 있다. 이를 실제 창업 의향·신청 완료와 같은 지표로 합산하지 않는다.
- 이벤트: 시작, 대화 완료, 결과 도달, 지역 링크 이동, 피드백. 원문 대화를 분석 이벤트에 넣지 않는다.
- 비회원 집계 단위와 중복 기준을 명시한다. 기기·세션 수를 실제 사람 수로 단정하지 않는다.

### F0. 계정 — P0 (2026-11-27 변경: 창업 준비는 로그인 후)
- 창업 준비(/mentor)는 회원가입·이메일 인증·로그인을 마친 사용자만 쓴다. 메인·지역 지원 목록·창업 유형 테스트는 로그인 없이 볼 수 있다. 로그인 후 원래 화면으로 돌아온다.
- **회원가입:** 이메일, 비밀번호, 비밀번호 확인(2회 입력), 개인정보 안내 동의. 두 비밀번호가 같은지와 규칙(8~64자, 영문과 숫자를 모두 포함)을 화면과 서버에서 모두 검사한다.
- **이메일 인증:** 가입하면 인증 메일(링크와 6자리 코드, 24시간 유효)을 보낸다. 인증 전에는 창업 준비를 시작할 수 없고 '인증 메일 다시 보내기'(1분에 1회)를 제공한다.
- **비밀번호 찾기:** 로그인 화면에서 이메일을 입력하면 복구 비밀번호(임시 비밀번호, 30분 유효, 1회용)를 메일로 보낸다. 가입 여부와 관계없이 같은 안내 문구를 보여 계정 존재를 드러내지 않는다. 요청은 이메일당 10분에 1회. 복구 비밀번호로 로그인하면 바로 새 비밀번호를 정하게 한다. 기존 비밀번호는 복구 비밀번호로 로그인할 때까지 그대로 쓸 수 있다.
- **비밀번호 변경 (내 정보):** 현재 비밀번호, 새 비밀번호 2회. 바꾸면 다른 기기의 로그인 세션을 끝낸다.
- 비밀번호·임시 비밀번호는 bcrypt(cost 10) + pepper(서버 secret, HMAC-SHA256 후 bcrypt)로 저장한다. 인증 토큰·코드는 SHA-256 해시로만 저장한다. 메일 발송은 Cloudflare Email Service 를 쓴다.
- **내 정보 기본 정보 (선택):** 나이, 거주지(부산·울산·경남의 구·군·시·군까지 고를 수 있다), 사업자 여부, 현재 직군. 입력하면 조건 확인(F4)의 기본값으로 쓴다. 모름·미입력을 허용하고 자격을 확정하지 않는다.
- **상담 횟수:** 1인(계정)당 한 주 12회. 사용자가 보낸 채팅(답·‘아직 모르겠어요’·‘건너뛰기’) 1개가 1회이고 첫 질문은 세지 않는다. 달력 주로 세어 일요일 0시(한국 시간)에 다시 채운다. 저장 키는 `chat:<계정 id>`. 초기화해도 돌아오지 않는다. 팀 계정은 제외한다.

### F18. 목록·상세 — P1
교육·상담·공간·지원사업 유형, 목적, 준비 단계로 탐색한다. 고급 필터보다 실제 이용 조건과 절차를 우선한다. 상세에는 공식 원문·확인일·상태를 표시한다.
- 정렬(정렬 select): 나에게 맞는 순 / 최근 공모 / 많이 본 공모 / 마감 임박 (기본 마감 임박).
- 지역 필터 (2026-11-27): 지역 선택(RegionPicker)에서 전체 / 부산 / 울산 / 경남을 고르고, 지역을 누르면 구·군(경남은 시·군) 칩이 펼쳐진다. 구·군은 공고 글에서 글자로 맞춘다. 지역 전체를 대상으로 하는 공고는 ‘○○ 전역’ 표시를 붙인다.
- 페이지 이동: 한 페이지 10건, 번호는 5개 창으로 보여 준다.
- 마감 표시: 마감 7일 이내는 ‘D-n’, 마감 당일은 ‘오늘 마감’ 배지를 붙인다.
- 관심 표시(하트): 로그인 사용자만. 누르기 전 테두리 하트, 누르면 색이 찬 하트. 계정에 저장(`likes:<userId>`, 최대 200개).
- 나에게 맞는 순 = 하트 누른 자료와 비슷함(도움 종류·산업·유형·기관) × 3 + 내 정보 조건 부합 칸마다 0.5 + 준비 단계 일치 1, 명시 조건 불일치 −3. 마감·종료는 뒤.
- 창업 준비 추천(F5)에서 하트는 같은 점수 묶음 안의 순서에만 쓴다. 하트만으로 후보가 되지 않는다.
- 상세의 조건 대조(F4)는 내 정보(나이·거주지·사업자 여부)를 쓴다. 대화에서 입력한 조건이 먼저이고, 비었거나 '모름'인 칸은 내 정보로 채운다.

### F13·F17. 지원서 작성 — P1 (2026-11-27, 반영 중)
- 모집 중인 공고 상세(/programs/:id)에서 로그인하고 이메일 인증을 마친 사용자가 지원서 초안을 만든다 (인증 전에는 403 `email_unverified`). 마감·종료된 공고는 만들 수 없다.
- 공고 양식은 DocWorker 컨테이너가 받아 Upstage Document Parse 로 읽는다 (URL 별 캐시). 양식을 못 읽으면 모의 양식 항목을 쓴다.
- Upstage Solar 가 신원 정보가 아닌 칸의 초안을 쓴다. 이름·연락처 같은 신원 칸은 채우지 않는다. 초안은 AI 제안이며 사용자가 확인한다.
- 화면 /applications/:id: 수정 → 제출 전 확인 → 작성 완료. 해보까는 제출하지 않는다. 작성 완료 뒤(또는 작성 중에도) 파일을 내려받아 공식 사이트에서 직접 신청한다. 서버 상태 이름(`completed` 등)과 `MOCK-…` 접수번호 생성은 서버에 남아 있지만 화면에는 보이지 않는다.
- AI로 다듬기: `POST /api/applications/:id/polish`. Solar 가 칸별 다듬은 글을 제안한다. 본인 정보 칸은 제외하고, 근거 없는 내용은 검사(`guard_text`)로 거른다. 지원서당 5회(넘으면 429 `polish_limit`), AI 가 꺼져 있으면 503 `ai_unavailable`. 저장은 하지 않는다. 사용자가 ‘이 글로 바꾸기’로 적용한 뒤 임시 저장해야 저장된다.
- 파일 내려받기: `GET /api/applications/:id/export?format=docx|pptx|hwpx`. 세 형식 모두 같은 내용을 채운다 (공통 양식은 DOCX 문서, PPTX 16:9 슬라이드(표지·신청인 정보·사업 내용 여러 장·확인), HWPX 문서). DocWorker 가 켜져 있고 공고 원본 양식이 채울 수 있는 형식(DOCX·HWPX·PPTX)이면 고른 형식과 달라도 원본 양식에 값을 채운다(`source: "form"`, 응답의 `format` 이 원본 형식). 원본이 HWP·PDF 처럼 채울 수 없는 형식이면 그 양식에서 읽은 항목 이름으로 공통 양식을 만든다(`source: "standard_form_fields"`). 원본 양식이 없으면 공통 양식(`source: "standard"`)이다. 공통 양식은 공문 형식이다: 제목 ‘창업지원사업 지원서’, 사업명·주관기관·작성일 표, ‘1. 신청인 정보’(본인 정보 칸, 비어 있으면 빈칸), ‘2. 사업 내용’, 확인 문장, 날짜, 신청인 서명란, ‘○○ 귀하’. 응답은 base64 JSON(`fileName`, `mimeType`, `fileBase64`, `source`, `format`). PDF 는 인쇄 화면에서 브라우저 ‘PDF로 저장’을 쓰고, HWP 는 HWPX 로 대신한다.
- 내가 찾은 제출 양식에 채우기: `POST /api/applications/:id/form-fill` `{fileName, fileBase64}`. 사용자가 공고 사이트에서 받은 양식(DOCX·HWPX·PPTX, 4MB 이하)을 올리면 항목 이름에 맞춰 지원서 내용을 채워 돌려준다. 항목 이름이 달라도 흔한 다른 이름(예: 대표자 이름 ↔ 성명·대표자명, 창업 아이템명 ↔ 사업명·과제명)으로 맞춘다. 응답에 채운 항목(`filled`)이 있다. HWP·PDF·PPT 는 422 로 새 형식으로 저장해 올리라고 안내하고, DocWorker 가 꺼져 있으면 503 `doc_worker_off`, 채울 칸을 못 찾으면 422 `no_match`. 이 경로만 요청 본문 6MB 까지 받는다.
- 상담 결과의 모집 중인 추천 공고마다 ‘지원서 작성’을 둔다.
- 초안은 상담 자료(구상, 요약, 답변)로 미리 채운다.
- 지원서 작성은 계정당 7일에 2회다 (서버 설정 `application_limit`). 넘으면 `POST /api/applications` 가 429 `application_limit` 을 돌려주고 다시 쓸 수 있는 날짜를 알린다. 남은 횟수는 `GET /api/applications/quota` 로 본다.
- 내 정보에 내 지원서 목록(F17)을 보여 준다. API 는 `/api/applications` (`packages/shared/src/api.ts`).
- 완료 기준: 열린 공고에서 초안 생성, 수정, 확인, 작성 완료, 파일 내려받기, 내 정보에서 목록 확인. AI·양식 읽기 실패 시에도 직접 입력으로 진행한다.

| 지역 자료 없음 | 없음 표시, 일반 준비 안내 유지 |
| 자격 정보 미입력 | 추가 확인 필요, 부합으로 확정하지 않음 |
| 종료된 프로그램 | 현재 모집 추천 제외 |
| AI 장애 | 재시도·수동 양식·검수된 안내 |
| 요약 수정 | 준비사항·관련 결과 재계산 |
| 문제 선택 변경 | 이전 입력 보존·문제 ID 갱신·대화/요약/추천 재평가 |
| 원하는 문제 없음 | 직접 입력·보류로 진행, 임의 선택 없음 |
| AI 제안 거절 | 거절 반영·탐색 중 표시·동일 제안 강요 없음 |
| 지역 변경 | 지역 배경·고객 가설·관련 경로 재평가, 같은 문구의 도시명 치환 금지 |
| 검토 지역과 거주지 다름 | 희망지와 지원 자격을 분리해 안내 |
| 산업 자료만 있고 이용 경로 없음 | 배경 사실만 제시하고 지원 경로는 미확인 표시 |
| 지역 연관성 약함 | 연관성 판단 어려움 표시, 구상을 임의 변경하지 않음 |
| 새로고침·초기화 | 기기 내 복구·삭제가 설명대로 동작 |

## 6. 의존 관계

F20 → F1 → F2 → F3 → F12
F21 + F7 → F4 → F5 + F6 + F11
F3 → F4(필요한 조건만 추가 입력) / F5
F9·F10은 비회원 핵심 흐름을 보조한다. F0·F8·F14·F18은 없어도 핵심 시연이 가능해야 한다.

## 7. 이번 지역성 보완의 최소 출력 계약

기존 응답을 삭제·교체하지 않고 F3 결과에 선택 필드 하나를 추가하는 안이다. 실제 필드명·공유 타입 수정은 개발 담당자가 기존 계약과 대조한다.

| 선택 필드 예시 | 의미 | 누락·빈 값 처리 |
|---|---|---|
| regional_context.region | 사용자가 검토하는 지역 | 미정 |
| regional_context.basis | 지역 배경과 구상의 접점 | 근거 부족 안내 |
| regional_context.source_ids | F21 지역 맥락 자료 ID | 빈 배열, 사실 주장 생성 금지 |
| regional_context.customer_hypothesis | 지역 고객 가설과 확인할 질문 | 미정 또는 미검증 표시 |
| regional_context.resource_ids | 검수된 지역 준비 경로 ID | 빈 배열, 경로 미확인 |
| regional_context.status | 검토할 근거 있음 / 추가 확인 필요 / 현재 자료로 연결 어려움 | 추가 확인 필요 |

사용자 사실·AI 가설 표시는 기존 F3 규칙을 재사용한다. 프론트는 필드 미존재 시 기존 결과를 정상 표시한다. 잘못된 참조 ID는 무시하고 확인 필요로 처리한다. 단순한 자료 수집·프롬프트·선택 필드·기존 카드 변경으로 우선 구현한다.

### 자기주도 탐색 선택 필드

기존 계약을 깨지 않는 선택 객체 예시다. 실제 필드명·공유 타입 변경은 개발 담당자가 확인한다.

| 필드 | 의미 | 미정 처리 |
|---|---|---|
| exploration.problem_id | 사용자가 고른 문제 ID | 직접 입력·보류이면 null |
| exploration.origin | 카드 선택 / 직접 입력 / 보류 | 보류 |
| exploration.selection_reason | 사용자가 말한 관심 이유 | 미정, AI 추정 금지 |
| exploration.direction | 사용자가 선택·수정한 접근 방향 | 아직 탐색 중 |
| exploration.direction_status | 사용자 입력 / AI 제안·미채택 / 사용자 선택 / 보류 | 보류 |

문제 원문 근거는 F21에서 참조하고 카드 변경 시 재검증한다. 선택 객체가 없어도 기존 상담은 동작한다. AI 제안·미채택 상태를 사용자 선택으로 표시하지 않는다.
