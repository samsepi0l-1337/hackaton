## 2. 계정

### F0. 회원가입·로그인 (P0)

- **입력:** 이메일, 비밀번호(8자 이상), 개인정보 안내 동의 체크. 소셜 로그인은 만들지 않는다.
- **출력:** 세션(HttpOnly 쿠키), 로그인 상태의 헤더.
- **규칙**
  - 비밀번호는 해시로만 저장한다.
  - 상담(F1~F13)·지원서(F13, F16)·내 정보(F17)는 로그인이 필요하다. 메인·공고 모음·창업 유형 테스트는 로그인 없이 쓸 수 있다.
  - 로그인이 필요한 화면에 들어가면 로그인 화면으로 보내고, 로그인 후 원래 화면으로 돌아온다.
  - 계정 삭제 시 그 계정의 모든 데이터를 지운다.
- **완료 조건:** 가입 → 로그아웃 → 다시 로그인하면 이전 상담 데이터가 보인다. 다른 계정으로 로그인하면 보이지 않는다.

## 3. 상담 (멘토링)

상담은 **① 사전 상담 폼 → ② 챗봇 되묻기 → ③ 요약 → ④ 결과**의 4단계다. 폼으로 구조화된 정보를 먼저 받아서 챗봇 질문을 줄이고, 규칙 판정(F4)에 필요한 값을 정확히 받는다.

### F1. 사전 상담 폼 (P0)

웹 폼으로 사업과 타겟층의 세부 데이터를 받는다. 3개 섹션, 한 화면에 한 섹션(휴대폰 기준).

**섹션 A. 나에 대해** — 자격 판정(F4)에 쓰는 값

| 항목 | 형식 | 필수 | 비고 |
|---|---|---|---|
| 나이(만) | 숫자 | ✓ | 15 ~ 34 |
| 창업 단계 | 선택: 예비(사업자 없음) / 1년 미만 / 1~3년 / 3~7년 | ✓ | |
| 사업자 개업일 | 날짜 | 단계가 예비가 아니면 ✓ | 창업 연차 계산 |
| 사업장(예정) 지역 | 선택: 부산 16개 구·군 / 부산 외 | ✓ | |
| 소속 | 선택: 대학생 / 대학원생 / 직장인 / 무직 / 기타 | | 대학 창업지원단 안내(F11) |
| 팀 규모 | 선택: 혼자 / 2~3명 / 4명 이상 | | |
| 창업 유형 테스트 결과 | 자동 채움 | | F19 결과가 있으면 |

**섹션 B. 하고 싶은 사업**

| 항목 | 형식 | 필수 | 비고 |
|---|---|---|---|
| 아이디어 한 줄 | 텍스트 | ✓ | 200자 이하 |
| 업종 | 선택: IT·플랫폼 / 제조 / 식품·외식 / 관광·문화 / 교육 / 헬스케어 / 해양·물류 / 친환경 / 커머스 / 기타 | ✓ | 지역 산업 태그와 연결 |
| 사업 형태 | 선택: 앱·웹 서비스 / 제품 판매 / 오프라인 매장 / 대행·용역 / 기타 | ✓ | |
| 해결하려는 문제 | 텍스트 | ✓ | 300자 이하 |
| 준비 상태 | 선택: 아이디어만 / 조사 중 / 시제품 있음 / 매출 있음 | ✓ | |
| 수익 방식 | 선택(복수): 판매 / 구독 / 수수료 / 광고 / 아직 모름 | | |

**섹션 C. 타겟 고객**

| 항목 | 형식 | 필수 | 비고 |
|---|---|---|---|
| 고객 유형 | 선택: 개인(B2C) / 사업자(B2B) / 공공기관(B2G) | ✓ | |
| 고객 연령대 | 선택(복수): 10대 / 20대 / 30대 / 40대 / 50대 이상 / 무관 | B2C면 ✓ | |
| 고객 지역 | 선택: 부산 / 동남권 / 전국 / 해외 | ✓ | |
| 고객 설명 | 텍스트 | ✓ | 예: "부산 대학가 자취생", 200자 이하 |
| 고객이 지금 쓰는 대안 | 텍스트 | | |
| 필요한 지원 | 선택(복수): 자금 / 공간 / 멘토링·교육 / 판로·마케팅 / 시제품 제작 / 네트워킹 | ✓ | 추천 점수에 반영 |

- **규칙**
  - 필수 항목이 비면 다음 섹션으로 넘어가지 않고, 빈 항목을 표시한다.
  - 입력값은 섹션마다 자동 저장한다. 다시 들어오면 이어서 쓴다.
  - 이전 상담이 있으면 이전 값을 채워서 보여준다.
- **출력:** 상담 프로필(위 항목 전체). F2·F3·F4·F5에 넘긴다.
- **완료 조건:** 폼을 끝까지 채우면 챗봇 단계로 넘어가고, 챗봇 첫 메시지가 폼 내용을 한 문장으로 다시 말한다.

### F2. AI 멘토 되묻기 — 챗봇 (P0)

- **입력:** 상담 프로필(F1).
- **동작**
  - 챗봇은 폼에 **없거나 짧은** 정보를 골라 질문 **정확히 3개**를 한 번에 하나씩 한다. 기본 후보: 고객이 왜 지금 대안에 불만인가 / 첫 고객 10명을 어디서 찾나 / 왜 부산에서 해야 하나.
  - 사용자는 질문마다 "건너뛰기"를 할 수 있다.
  - 3개가 끝나면 "요약 보기" 버튼을 보인다. 그 뒤 자유 질문은 계속할 수 있다(질문 수 제한은 설계에서 정함).
  - 응답은 글자 단위로 이어서 표시한다(스트리밍).
- **규칙:** 지원사업 이름·금액·마감일을 챗봇이 직접 말하지 않는다. 지원사업 정보는 결과 화면(F5)에서 데이터로만 보여준다.
- **완료 조건:** 첫 응답 10초 이내. 질문 3개(건너뛰기 포함) 후 요약 단계로 갈 수 있다.

### F3. 아이디어 1장 요약 (P0)

- **입력:** 상담 프로필 + 챗봇 대화.
- **출력:** 문제 / 고객 / 해결책 / 수익 구조 / 부산 연결점, 항목별 2~3줄.
- **규칙:** 사용자가 항목을 직접 고칠 수 있다. 고친 요약이 추천(F5)과 초안(F13)의 근거가 된다.

### F4. 자격 판정 — 규칙 (P0)

- **입력:** 상담 프로필(나이, 창업 연차, 지역, 소속), 공고(대상 연령 `biz_trgt_age`, 창업 연차 `biz_enyy`, 지역 `supt_regin`, 신청 대상 `aply_trgt`, 마감 `pbanc_rcpt_end_dt`).
- **출력:** 공고마다 `가능` / `확인 필요` / `불가` 와 판정 근거(어떤 조건이 맞고 어떤 조건이 없는지).
- **규칙**
  - AI를 쓰지 않는다. 같은 입력은 항상 같은 결과다.
  - 공고에 조건 값이 없거나 해석할 수 없으면 `확인 필요`.
  - 지역: 부산 또는 전국 공고만 `가능` 후보. 다른 지역 한정이면 `불가`.
  - 마감: 한국 시간 기준 오늘이 마감일보다 뒤면 `불가`. 마감일이 없는 상시 모집은 마감으로 떨어뜨리지 않는다.
- **완료 조건:** 판정 규칙마다 단위 테스트(경계값: 만 39세/40세, 창업 3년/3년+1일, 마감일 당일).

### F5. 지원사업 Top3 (P0)

- **입력:** F4 판정 결과, 상담 프로필, 요약.
- **동작**
  1. `불가`를 뺀다.
  2. 점수 = 관련도(jev 또는 규칙 점수) + 필요한 지원 일치 + 마감 임박 가중치. `확인 필요`는 감점.
  3. 상위 3개를 보여준다. 3개가 안 되면 있는 만큼 보여주고 공고 모음(F18) 링크를 준다.
- **카드 항목:** 공고명, 기관, 판정 배지, 마감 D-day, 지원 내용 요약, 원문 링크, 추천 이유(F6), 평가 버튼(F10), "지원서 만들기"(F13).
- **완료 조건:** 목록 3초 이내. AI 장애 시 규칙 점수만으로 Top3가 나온다.

### F6. 추천 이유 (P0)

- 카드마다 1~2줄. 공고 원문과 사용자 요약에 있는 내용만 쓴다. 금액·조건을 새로 만들지 않는다.
- 목록을 먼저 보여주고, 이유는 이어서 채운다.

### F9. 대화 기억 (P1)

- 계정별로 상담 프로필, 대화, 요약, 결과를 저장한다.
- 재방문 시 상담 화면에서 "이어서 하기 / 새 상담" 중 하나를 고른다. 이어서 하면 새 공고가 반영된 Top3를 다시 계산한다.

### F10. 추천 평가 (P1)

- 카드마다 "관련 있음 / 없음". "없음"을 누른 공고는 그 계정의 다음 Top3에서 뺀다.
- 결과 화면 아래 질문 "몰랐던 지원사업을 찾았나요?(예/아니오)" — 발견율 지표.

### F11. 찾아갈 기관 (P1)

- 사업장 지역(구)과 소속을 기준으로 부산 창업 지원기관·대학 창업지원단 2~3곳. 이름, 주소, 하는 일, 링크.
- 기관 목록은 팀이 수동으로 만든 데이터(D 담당).

### F12. 7일 실행 계획 (P1)

- Day 1~7 할 일 체크리스트. 첫 항목은 Top3 중 마감이 가장 가까운 사업과 연결한다.
- 체크 상태를 저장한다.

## 4. 지원서

### F13. 지원서 초안 (P1)

- **입력:** 선택한 공고, 그 공고에서 내려받은 신청 양식의 항목 목록(F16 단계 1), 요약, 상담 프로필.
- **출력:** 양식 항목별 초안. 사용자가 항목마다 고칠 수 있다.
- **규칙:** 신원 정보(이름, 연락처, 이메일)는 AI가 만들지 않는다. 사용자가 입력한다. 양식에 맞는 글자 수를 지킨다.

### F16. 지원서 자동 제출 (P1)

- **구성:** Cloudflare Agents SDK의 agent worker(제출 1건 = 에이전트 1개, 상태는 Durable Object) + **Container**(양식 내려받기·읽기·작성) + Browser Rendering(웹 접수). Workers Paid($5) 포함량 안에서만 쓴다.
- **양식 처리 (공고마다 그때그때)**
  1. Container가 공고 상세 페이지(`detl_pg_url`)에서 첨부 신청 양식(HWP·HWPX·DOCX·PDF)과 신청 경로를 찾아 내려받는다.
  2. 양식에서 항목 이름·글자 수 제한·필수 여부를 읽어 항목 목록을 만든다. 양식이 없거나 읽을 수 없으면 공고 본문에서 항목을 뽑고, 그래도 안 되면 `사용자 조치 필요`.
  3. 항목 목록으로 초안(F13)을 만들고 사용자가 고친다.
  4. 승인 후 Container가 **원래 양식 형식 그대로** 값을 채운 파일을 만든다. 사용자는 승인 화면에서 미리 볼 수 있다.
  5. 신청 경로에 따라 제출한다: 웹 접수는 Browser Rendering으로 입력·파일 첨부, 이메일 접수는 채운 파일을 첨부해 보낸다.
- **단계와 상태**

| 상태 | 의미 | 다음 |
|---|---|---|
| `양식 준비` | 양식 내려받기·항목 읽기 | `작성 중` 또는 `사용자 조치 필요` |
| `작성 중` | 사용자가 초안을 고치고 신원 정보 입력 | 승인 요청 |
| `승인 대기` | 제출할 값 전체를 사용자에게 보여줌 | 승인 → `입력 중`, 취소 → 끝 |
| `입력 중` | 에이전트가 양식을 열고 값을 채움 | `제출 중` 또는 `사용자 조치 필요` |
| `사용자 조치 필요` | 본인인증·CAPTCHA·파일 첨부·모르는 필수 항목 | 사용자에게 원문 링크와 입력값을 넘김 |
| `제출 중` | 최종 제출 버튼 누름 | `완료` 또는 `실패` |
| `완료` | 접수 확인 화면 캡처, 접수 번호 저장 | |
| `실패` | 실패 이유 저장, 재시도 1회 허용 | |

- **규칙**
  - 승인 기록(값 전체, 시각)이 없으면 제출하지 않는다.
  - 승인한 값만 입력한다. 양식에 승인되지 않은 필수 항목이 있으면 `사용자 조치 필요`.
  - 제출 직전에 마감을 다시 확인한다.
  - 같은 계정·같은 공고는 `완료`가 한 번만 있다.
  - 신청 사이트 로그인·본인인증·CAPTCHA가 필요하면 `사용자 조치 필요`로 멈추고 채운 파일과 원문 링크를 넘긴다.
  - 팀의 모의 접수 양식을 시연 백업으로 둔다.
- **완료 조건:** 실제 공고 1건 이상에서 양식 내려받기 → 채운 파일 생성까지 동작. 모의 양식에서 승인 → 완료까지 동작. 진행 상태가 화면에 실시간으로 바뀐다.

### F17. 제출 내역 (P1)

- 계정별 제출 목록: 공고명, 제출 시각, 상태, 접수 확인 캡처·번호, 원문 링크.

## 5. 공고

### F7. 마감 정리 (P0)

- 매일 새벽(한국 시간) 마감 지난 공고를 추천·목록 기본 보기에서 뺀다. 데이터는 지우지 않는다.

### F8. 새 공고 반영 (P1)

- 매일 새벽 K-Startup `getAnnouncementInformation02`에서 부산·전국 모집 중 공고를 받아 공고 번호 `pbanc_sn` 기준으로 추가·갱신한다.
- 부산시·구·대학 자체 공고는 우선 넣지 않는다(F21).

### F18. 공고 모음·검색 (P0)

- **목록:** 모집 중 공고 전체. 기본 정렬은 마감 임박순.
- **필터:** 지역(부산 / 전국), 지원 분야(`supt_biz_clsfc`), 창업 단계, 대상 연령, 마감 기간(7일 이내 / 30일 이내 / 상시), 판정(로그인하고 상담 프로필이 있을 때만: 가능 / 확인 필요).
- **검색:** 공고명·기관·지원 내용 키워드.
- **정렬:** 마감 임박순 / 최신 등록순.
- **상세:** 공고명, 기관, 지원 분야, 지역, 접수 기간, D-day, 신청 대상, 대상 연령, 창업 연차, 지원 내용, 원문 링크. 로그인 + 프로필이 있으면 판정 결과와 근거(F4), "이 사업으로 지원서 만들기"(F13).
- **규칙:** 마감 지난 공고는 기본으로 숨긴다. 원문 링크는 항상 보인다.
- **완료 조건:** 필터·검색 결과 1초 이내(목록 100개 기준). 20개씩 나눠 보여준다.

### F15. 대학생 전체 지원 확장 (P2)

- 월세·교통·취업 등 대학생 지원을 공고 모음에 "대학생 지원" 분야로 추가.

### F21. 부산시·구·대학 자체 공고 (P2)

- K-Startup에 없는 부산시·구·대학 창업 지원 공고 10개 정도를 K-Startup과 같은 형식으로 수동 추가. 시간이 남으면 한다.

## 6. 창업 유형 테스트

### F19. 창업 유형 테스트 — MBTI형 (P1)

- **목적:** 가볍게 들어와서 상담으로 이어지게 하는 유입 기능. 로그인 없이 쓸 수 있다.
- **구성:** 4개 축 × 3문항 = **12문항**, 문항마다 2지선다. 1~2분 안에 끝난다.

| 축 | 글자 | 의미 |
|---|---|---|
| 실행 방식 | **A**(Action, 먼저 해 본다) / **P**(Plan, 먼저 계획한다) | |
| 일하는 방식 | **S**(Solo, 혼자 빠르게) / **T**(Team, 함께 크게) | 팀 규모·네트워킹 지원 연결 |
| 관심 중심 | **D**(Tech·제품) / **H**(Human·사람·서비스) | 업종 추천 연결 |
| 위험 태도 | **C**(Challenge, 도전) / **K**(Keep, 안정) | 지원 유형(자금 vs 교육) 연결 |

- **결과:** 16개 유형(예: `APDC`) 중 하나. 유형마다 이름, 한 줄 설명, 강점 2개, 주의할 점 1개, 잘 맞는 업종 예시, 먼저 보면 좋은 지원 분야.
- **연결:** 결과 화면에 "이 유형으로 상담 시작" 버튼. 누르면 결과를 사전 상담 폼(F1)에 넣는다(로그인 후). 결과 공유 링크(이미지 없이 URL).
- **규칙**
  - 결과는 재미·참고용이며 추천 판정(F4)에 쓰지 않는다. 결과 화면에 그렇게 표시한다.
  - 공식 MBTI 문항·유형 설명을 쓰지 않는다. 문항·설명은 팀이 새로 쓴다. "MBTI"는 등록 상표이므로 화면 이름은 "창업 유형 테스트"로 한다.
  - 로그인하지 않으면 결과는 브라우저에만 두고, 로그인하면 계정에 저장한다.
- **완료 조건:** 12문항 완료 → 결과 화면 → 상담 시작 시 폼에 결과가 채워진다.
