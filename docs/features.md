## 2. 시작과 대화

### F1. 준비 상태·관심 입력

**입력**
- 준비 상태: ‘관심은 있지만 아이디어가 없어요 / 생각해둔 아이디어가 있어요 / 구체적으로 준비 중이에요’.
- 아이디어 있음: 해보고 싶은 일 200자 이내.
- 아이디어 없음: 관심 분야 또는 자신의 경험 1개 이상 선택·입력. ‘직접 적기’ 허용.
- 활동 지역: 부산 구·군 또는 아직 미정. 지원 거주요건과 같은 값으로 취급하지 않음.

**규칙**
- 처음부터 업종 코드·B2B·수익 구조·사업자 개업일을 요구하지 않는다.
- 아무 입력도 없는 경우에만 선택을 안내한다. 긴 설명을 강요하지 않는다.
- 관심 분야를 선택했다고 창업 업종을 확정하지 않는다.
- 기존 사업자 이용자는 준비 중 경로로 이동하되 전문 경영 자문은 제공 범위가 아님을 안내한다.

**완료 기준:** 두 진입 경로 모두 비회원으로 F2에 진입한다.

### F2. 쉬운 질문 기반 창업 탐색

**입력:** F1과 현재 대화.
**출력:** 한 번에 질문 하나, 예시 또는 선택지, ‘아직 모르겠어요’, ‘건너뛰기’.
**질문 범위:** 기본 최대 3개. 충분히 답했다면 일찍 정리할 수 있다. 3개 후 임의의 추가 질문으로 결과 진입을 막지 않는다.

| 알아볼 내용 | 사용자에게 제시할 표현 예시 |
|---|---|
| 관심의 계기 | 이 일을 해보고 싶어진 경험이 있나요? |
| 도움받을 사람 | 어떤 사람이 이용하면 좋을까요? 아직 정하지 않아도 괜찮아요. |
| 준비 상태 | 지금까지 알아보거나 준비한 것이 있나요? |
| 관심만 있는 경우 | 선택한 분야에서 판매·제작·서비스 중 살펴보고 싶은 방향이 있나요? |

**규칙**
- 질문은 면접·심사처럼 채점하지 않는다. 과도한 칭찬이나 성공 가능성 평가를 하지 않는다.
- 아이디어가 없으면 검토할 방향을 최대 2개 제안하고 본인이 선택·수정하게 한다. 모두 선택하지 않아도 결과를 볼 수 있다.
- 사용자가 모르는 항목은 미정으로 저장한다. 추정으로 채우지 않는다.
- 사용자에게 없는 고객 인터뷰·매출·팀·경험을 만들지 않는다.
- 기관·금액·마감일은 검수 데이터에서만 제시한다.
- 동일 응답 재전송과 중복 결과 생성을 막는다.

**완료 기준:** 아이디어 있음·없음·모든 질문 건너뛰기에서 모두 결과로 갈 수 있다. 장애 시 재시도와 수동 정리 양식이 보인다.

### F3. 창업 구상 요약·수정

**출력 항목**
1. 관심 분야와 하고 싶은 일.
2. 도움을 주고 싶은 대상.
3. 해결해보고 싶은 불편 또는 제공할 가치.
4. 아직 확인하지 않은 사항.

각 항목에 ‘직접 입력 / AI 제안·미검증 / 미정’을 표시한다. 편집했다고 실제 검증된 사실이 되는 것은 아니다. 수익 구조와 지역 연계는 근거가 없으면 필수로 생성하지 않는다.

**수정 규칙:** 수정 내용이 추천·준비 안내에 반영된다. 기존 준비사항 체크는 재생성 전에 사용자에게 알리고 초기화한다.

**완료 기준:** 원래 입력이 요약에서 유지되고 AI 제안은 구분된다. 수정 후 결과가 갱신된다.

## 3. 준비 안내와 지역 연결

### F12. 우선 준비사항과 후속 준비 안내

**입력:** 사용자가 확인한 요약과 현재 준비 상태.
**출력:** 우선 준비사항 1개, 후속 준비사항 최대 2개.

각 항목은 ‘무엇을 준비할지 / 지금 필요한 이유 / 진행 방법 / 준비 결과로 남길 것’을 포함한다.

예: 고객이 미정이면 ‘이용할 사람의 상황 구체화’를 우선으로 제시한다. 구상이 정리되고 학습이 필요하면 실제 입문 교육을 안내한다. 일정 기간 계획이나 공고 신청을 모든 사람에게 일률적으로 부여하지 않는다.

**규칙**
- 자금 지출·사업자등록·지원금 신청을 기본 첫 단계로 권하지 않는다.
- 검증 전 수익성과 시장 수요를 확정하지 않는다.
- 체크는 ‘준비 완료 표시’이며 실제 수행의 객관적 증거로 취급하지 않는다.

**완료 기준:** 요약이 미정이어도 안내가 나오며, 다른 준비 상태에 동일한 계획을 반복하지 않는다.

### F21. 검수된 부산 지역 데이터

데이터는 교육·상담·공간·지원사업을 구분한다. 첫 배포는 5~10개를 목표로 하되 확보 수와 미확인 항목을 정직하게 기록한다.

**필드:** ID, 유형, 제목, 기관, 공식 URL, 대상, 준비 단계, 내용, 신청·문의 절차, 사전 준비, 이용 가능 지역, 소속 제한, 기간·비용, 모집 상태, 확인일, 원문 근거.

- 누락은 ‘확인 필요’, 무료 여부가 없으면 비용을 추정하지 않는다.
- 기관 상시 안내와 기간 한정 사업을 구분한다.
- 과거 안내책자를 현재 모집 중인 프로그램의 증거로 사용하지 않는다.
- 자료 충돌 시 추천을 보류하고 공식 문의 경로를 제공한다.

**완료 기준:** 표시하는 각 데이터에 공식 링크·확인일이 있고, 기획 담당자가 대상·기간·이용 절차를 검수했다.

### F4. 조건 대조

지원 상세 확인에 필요한 경우에만 나이·거주지·소속·사업자 여부를 묻는다. ‘모름/입력하지 않음’을 허용한다.

**출력:** ‘입력 조건 부합 / 추가 확인 필요 / 명시 조건 불일치’와 항목별 근거.
- 입력 조건 부합은 수집·검수한 조건 범위에서의 비교이며 최종 신청 자격 보장이 아니다.
- 사용자 정보·원문 조건이 없거나 일부 조건을 확인하지 못하면 추가 확인 필요.
- 명시 조건 불일치와 다른 준비 단계의 추천은 구분한다.
- 자격 판단을 AI의 유사도 점수로 대신하지 않는다.
- 상시 모집은 명시 근거가 있을 때만 상시로 취급한다.

**완료 기준:** 미입력·모호한 원문·나이 경계·마감 당일/종료 사례의 기대 결과가 확인된다.

### F5. 단계별 지역 지원 추천 / F6. 이유

검수 데이터 중 준비 단계·목적·이용 조건을 기준으로 최대 3개를 제시한다. 기관·교육·지원금 중 사용자 상황에 맞는 유형을 선택하며 개수나 마감 임박 여부를 위해 부적절한 자료를 채우지 않는다.

**카드:** 유형, 제목, 기관, 현재 단계와 연결되는 이유, 얻을 도움, 이용 절차, 조건 상태, 모집 상태, 원문, 확인일.
- ‘유사도’를 ‘선정 확률’로 표시하지 않는다.
- 맞는 결과가 없으면 명시하고 F12 준비 안내를 유지한다.
- 이유는 사용자 확인 내용과 원문에 근거한다.
- AI 장애 시 검수 데이터와 규칙 기반 설명을 제공한다.

**완료 기준:** 미정 사용자·적합 자료 없음·일부 조건 미확인·마감된 자료에서 오해 없이 결과가 나온다.

### F11. 기관과 이용 경로

기관명·주소만 제시하지 않고 어떤 도움을 요청할 수 있는지, 대상, 공식 문의/신청 경로, 준비할 내용을 보여준다. 실제 상담 가능 여부를 데이터 없이 확정하지 않는다. 대학 기관은 재학생·졸업생·외부인 조건을 구분한다.

### F7. 모집 상태 관리 / F8. 자동 갱신

F7은 P0. 한국 시간으로 기간과 접수 상태를 확인하고 종료된 프로그램을 현재 모집 중 추천에서 제외한다. 마감일만 있고 시각이 없으면 정확한 종료 시각을 확인하도록 표시한다. 상시 기관 안내는 기간 한정 프로그램과 별도로 보여준다.

F8은 P1. K-Startup API 연동 등 자동 수집은 선택이다. 실패하면 마지막 검수 자료와 확인일로 동작하며 오래된 자료를 최신으로 표시하지 않는다.

## 4. 저장·검증·보조 기능

### F9. 현재 기기 저장·초기화 — P0
- 현재 기기에 진행 상태와 요약을 저장해 새로고침 시 복구한다.
- 기기·브라우저가 바뀌면 이어지지 않는다는 안내를 제공한다.
- 초기화하면 로컬 상태를 지운다. 진행 중 서버에 전달된 데이터와 로그의 보관 범위는 별도로 명시한다.
- 원문 대화가 담긴 결과를 자동 공개 링크로 만들지 않는다.

### F10. 피드백 — P0
- 결과 후 유용/아쉬움과 선택적 이유를 받는다.
- 사용 전후 동일한 준비 방향 이해도 문항을 선택적으로 제공한다.
- 이벤트: 시작, 대화 완료, 결과 도달, 지역 링크 이동, 피드백. 원문 대화를 분석 이벤트에 넣지 않는다.
- 비회원 집계 단위와 중복 기준을 명시한다. 기기·세션 수를 실제 사람 수로 단정하지 않는다.

### F0. 계정 / F14. 통계 화면 — P1
- 기존 이메일·비밀번호 계정이 있다면 재방문용으로 유지할 수 있으나 체험을 차단하지 않는다.
- 비밀번호 해시와 계정별 데이터 분리를 유지한다.
- 비회원 상태를 계정에 옮길 때 선택·안내를 제공한다.
- 팀 통계 화면은 집계만 표시하고 접근을 제한한다. 화면을 못 만들면 같은 지표를 집계 파일로 검증할 수 있다.

### F18. 목록·상세 — P1
교육·상담·공간·지원사업 유형, 목적, 준비 단계로 탐색한다. 고급 필터보다 실제 이용 조건과 절차를 우선한다. 상세에는 공식 원문·확인일·상태를 표시한다.

### F20. 메인 — P0
주된 행동은 ‘창업 준비 시작하기’. 입력 부담과 결과 예시를 설명한다. 모집 공고 수·마감은 보조 정보이며 핵심 약속은 구상 정리와 준비 경로다.

### P2 후속 범위
F13 지원서 초안, F15 일반 청년지원, F16 자동 제출, F17 제출 내역, F19 성향 테스트는 이번 핵심 흐름의 의존 기능이 아니다. 별도 팀 승인 후 기존 명세를 재검토한다. 이 문서는 외부 제출 기능의 구현 완료를 요구하지 않는다.

## 5. 전체 수용 시나리오

| 상황 | 기대 동작 |
|---|---|
| 막연한 아이디어 있음 | 쉬운 질문 후 요약·준비사항·관련 경로 |
| 아이디어 없음 | 관심 탐색·선택 후 요약, 미정 허용 |
| 전부 모름·건너뛰기 | 추정 사실 없이 미정 요약과 탐색 준비 안내 |
| 지역 자료 없음 | 없음 표시, 일반 준비 안내 유지 |
| 자격 정보 미입력 | 추가 확인 필요, 부합으로 확정하지 않음 |
