# PRD: 부산 청년 창업 길잡이

> 상태: 팀 피드백용 수정안. GitHub 반영 전.
> 기준: 원본 main 8ef815ee50f99601572fd0da68545b34c8c3c734.
> 이번 수정은 제품 방향 제안이다. 기존 팀 결정 중 변경되는 항목은 아래에 명시한다.

## 1. 제품의 목적

**창업 경험이 없는 부산 청년이 자신의 관심과 아이디어를 창업 구상으로 정리하고, 준비 단계에 맞는 지역 지원 경로를 선택하도록 돕는다.**

궁극적 목표는 창업의 진입 장벽을 낮추고, 창업을 자신과 무관한 일이 아니라 검토하고 도전할 수 있는 선택지로 인식하게 하는 것이다. 제품은 사업 성공을 보장하거나 모든 이용자에게 사업자등록·지원금 신청을 권하지 않는다. 준비와 탐색도 창업 참여의 유효한 단계로 다룬다.

핵심 기능은 **대화를 통한 창업 구상 정리와 단계별 준비 안내**다. 지원사업 검색은 이 과정에 필요한 교육·상담·자원을 연결하는 수단으로 배치한다.

## 2. 문제정의와 근거 수준

### 2.1 우선 검증할 사용자 문제

> 창업에 관심은 있지만 경험이 없는 청년이 자신의 생각을 사업 용어로 설명하기 어렵고, 현재 단계에 필요한 준비와 이용 가능한 도움을 구분하지 못해 탐색을 중단한다.

이 문장은 사용자 인터뷰 전의 가설이다. 정보 부족, 용어 이해, 자신감, 자금 부족, 시간 부족을 같은 원인으로 묶지 않는다. 최근 창업 정보를 찾아본 사람이 어디에서 멈췄는지 확인해야 한다.

### 2.2 기존 기획에서 발견한 제품상의 모순

| 기존 구조 | 문제 | 수정 방향 |
|---|---|---|
| 상담 전에 사업·고객·수익 방식 입력 | 초보자가 상담으로 알아가야 할 내용을 선행 지식으로 요구 | 일상 언어로 입력하고 대화 중 구체화 |
| 가입해야 상담 시작 | 가치를 확인하기 전에 계정 생성 필요 | 핵심 흐름은 비회원 체험 |
| 지원사업 Top3와 자동 제출 중심 | 창업 준비 이전의 사용자를 바로 신청 단계로 이동 | 창업 구상·준비사항을 먼저 제시 |
| 지역 자체 공고는 P2 | 지역성을 설명할 핵심 자료가 선택 기능에 머묾 | 소수의 검수된 부산 경로를 P0 데이터로 확보 |
| 성향 테스트로 유형 부여 | 재미가 실제 준비 방향의 근거처럼 받아들여질 수 있음 | 초기 버전에서는 제외하고 현재 준비 상태를 확인 |

### 2.3 사회적 배경과 지역 문제의 구분

청년 일자리와 정착은 관심 배경이며, 이 웹서비스가 해커톤 기간에 해결했다고 주장할 성과는 아니다. 청년 유출의 원인이나 외국인 유학생 고용과 일자리의 관계는 검증된 근거 없이 제품 필요성에 사용하지 않는다.

창업 입문의 어려움은 전국 공통 문제다. 부산에서의 유효성은 지역 사용자의 실제 장애물과 지역의 교육·상담·지원 경로를 연결한 결과로 입증해야 한다. 부산 시범 서비스가 부울경 전역을 이미 지원하는 것처럼 표현하지 않는다.

## 3. 사용자와 지원 범위

| 대상 | 상황 | 제공할 가치 |
|---|---|---|
| 주 사용자 | 창업 경험이 없고 관심 분야나 막연한 아이디어가 있음 | 생각 정리, 용어 설명, 우선 준비사항 |
| 탐색 사용자 | 관심은 있지만 아이디어가 없음 | 관심·경험을 바탕으로 검토할 방향을 제안하고 본인이 선택 |
| 보조 사용자 | 구상은 있고 교육·상담·지원이 필요함 | 관련 지역 경로와 조건 확인 |
| 초기 범위 밖 | 운영 중 기업의 전문 경영·투자·법률·세무 문제 | 해당 전문기관 안내, 일반 AI 상담으로 해결했다고 주장하지 않음 |

학교 재학 여부나 특정 연령대만으로 체험을 막지 않는다. 개별 지원의 연령·소속·사업자 요건은 해당 자료의 명시 조건에 따라 확인한다.

| 비교 대상 | 공식 안내에서 확인한 제공 영역 | 우리 제품에서 검증할 추가 가치 |

## 5. 핵심 사용자 흐름

메인 → 준비 상태·관심 입력 → 쉬운 질문 최대 3개 → 창업 구상 요약 확인·수정 → 우선 준비사항 1개와 후속 준비사항 최대 2개 → 관련 부산 교육·상담·지원 경로 확인.

- 아이디어가 없으면 관심 분야와 경험을 출발점으로 삼는다.
- 모르는 답변을 허용하며 미확정 항목으로 남긴다.
- 사용자가 명시한 내용과 AI가 제안한 가설을 구분한다.
- 지원사업을 보고 싶을 때만 필요한 자격 정보를 추가로 받는다.
- 맞는 지역 경로가 없으면 없다고 안내하고 범용 준비 안내를 제공한다.

## 7. 성공 기준과 검증

아래 수치는 팀 내부의 제안 목표이며 실측 성과가 아니다.

| 지표 | 제안 목표·방법 | 해석 |
|---|---|---|
| 대상 사용자 체험 | 10명 목표, 창업 경험·관심 상태 구분 | 참가자 전체를 대상 사용자로 간주하지 않음 |
| 흐름 완료 | 시작 대비 결과 도달 수·비율 | 가입 수로 대체하지 않음 |
| 자력 사용 | 직접 관찰한 사용자 중 도움 없이 진행한 수 | 모르는 항목에서 막히는지 기록 |
| 준비 방향 이해 | 결과 후 본인이 우선 준비사항과 이유를 설명할 수 있는지 | 체크박스 클릭과 별도로 관찰 |
| 접근성 체감 | 사용 전후 ‘무엇부터 준비할지 알고 있다’ 1~5점 | 문항·표본 수·변화량 함께 공개 |
| 지역 연결 | 공식 상세·문의·신청 링크 이동 | 클릭을 실제 상담·신청 완료로 부르지 않음 |
| 데이터 품질 | 표시한 지역 경로 모두 출처·확인일 보유 | 마감 자료를 모집 중으로 오표시한 건수 기록 |

인상적인 답변 생성보다 사용자가 자신의 말로 설명하는지 확인한다. 사용 후에도 준비 방향이 불분명하면 질문과 결과를 수정한다. 작은 표본은 초기 사용성 검증으로 제시한다.

## 8. 데이터와 AI 요구사항

- 첫 배포는 부산 지역 교육·상담·공간·지원 경로 5~10개를 목표로 수동 검수한다. 목표 수를 채우기 위해 자료를 만들지 않는다.
- 자료별로 공식 링크, 운영기관, 대상, 지원 내용, 이용 절차, 준비사항, 모집 상태, 기간, 확인일을 보유한다.
- 대학 프로그램은 외부인 이용 가능 여부를 확인한다. 기관 위치와 신청 가능 지역을 구분한다.
- API는 원문으로 연결하는 수단이며, 요약 필드만으로 모든 자격을 확인했다고 표시하지 않는다.
- 조건은 규칙으로 대조하고 AI는 설명·대화·구상 정리를 맡는다.
- 결과는 ‘입력 조건 부합 / 추가 확인 필요 / 명시 조건 불일치’. 부합은 최종 자격 보장이 아니다.
- 데이터나 사용자 답변이 없으면 unknown으로 유지한다. AI가 고객 수·수익성·지역 산업 연계·기관 서비스·모집일을 만들지 않는다.
- AI 실패 시 재시도와 함께 사용자가 직접 구상·준비사항을 정리할 수 있는 기본 양식을 제공한다.

## 9. 구현·운영 기준

- 기존 Cloudflare 배포와 국산 AI 활용 방향은 유지하되 특정 SDK를 제품 차별점으로 설명하지 않는다.
- 기존 비용 상한 방향을 유지한다. 플랜·포함량은 구현 시 공식 문서로 재확인하며 이번 문서는 최신 가격을 보증하지 않는다.
- 핵심 체험에 이름·연락처·비밀번호를 요구하지 않는다. 나이·소속 등은 선택한 지원의 조건 확인에 필요한 시점에 받는다.
- API 키는 서버에서 관리한다. 대화 전 서버·외부 AI 전송 범위를 알리고, 분석 이벤트에는 대화 원문을 넣지 않는다.
- 비회원 저장은 현재 기기에 한정하며 초기화 가능하게 한다. 결과를 자동 공개하지 않는다.
- 소규모 화면에서 한 번에 한 질문을 제공하고, 기술 용어는 일상 표현과 예시로 설명한다.

## 10. 팀 작업과 개발 중인 내용의 적용

| 역할 | 우선 작업 | 완료 증거 |
|---|---|---|
| 프론트엔드 | 시작·대화·결과 흐름, 수정·뒤로 가기·빈 상태 | 비회원으로 끝까지 사용 |
| 백엔드·데이터 | 지역 경로 데이터, 조건·모집 상태 관리 | 근거·확인일·미확인 처리 |
| AI | 한 번에 한 질문, 사실/가설 구분, 준비 안내 | 아이디어 유무·건너뛰기·장애 사례 점검 |
| 기획·검증 | 대상 사용자 확인, 공식 자료 검수, 전후 기록 | 실제 피드백과 수정 이유 |

이미 개발 중이면 먼저 F1 질문과 F3·F12 결과 문구를 바꾼다. 다음으로 로그인 강제 해제와 지역 데이터 연결을 검토한다. 새로운 기능을 추가하기보다 기존 상담·요약·기관 안내를 재배치한다.

‘창업을 더 친숙한 선택지로 만든다’는 목표의 타당성과 동남권 특성은 아직 입증되지 않았다. 질문의 친절함만으로 차별화됐다고 보지 않는다. 실제 대상 사용자가 기존 방식보다 준비 방향과 지역 지원을 이해하기 쉬웠는지 확인한 뒤 발표 주장을 정한다.

이 수정안은 세 문서만 대상으로 한다. README와 기존 아이디어 문서는 이번 범위에서 수정하지 않았으므로, 반영 후에는 최신 기준이 본 PRD임을 팀이 공유해야 한다.
