# PRD: 해보까

> 상태: 개정안(PR #7)은 main 에 반영됐다. 운영 주소는 https://haeboka.dreamp.org 이다.
> 기능별 구현 상태는 6절 표와 16절을 본다. 백엔드는 Rust → WebAssembly Cloudflare Worker 하나다.
> 기존 팀 결정 중 변경된 항목은 16절에 명시한다.

## 1. 제품의 목적

**창업 경험이 없는 청년이 자신의 관심과 아이디어를 부울경의 산업·상권·지원 자원과 연결해, 지역에서 창업할 가능성과 준비 경로를 구체적으로 검토하도록 돕는다.**

궁극적 목표는 창업의 진입 장벽을 낮추고, 창업을 자신과 무관한 일이 아니라 검토하고 도전할 수 있는 선택지로 인식하게 하는 것이다. 제품은 사업 성공을 보장하거나 모든 이용자에게 사업자등록·지원금 신청을 권하지 않는다. 준비와 탐색도 창업 참여의 유효한 단계로 다룬다.

핵심 기능은 **사용자가 지역 문제를 살펴보고 직접 선택한 탐색 방향을 창업 구상과 준비 경로로 구체화하는 것**이다. AI는 문제 선택과 창업 아이템 결정을 대신하지 않고 선택 이유·경험·관심을 정리하도록 돕는다. 지원사업 검색은 필요한 교육·상담·자원을 연결하는 수단이다. 지역에서 창업을 검토할 이유를 제공하되 성공이나 다른 지역 대비 우위를 단정하지 않는다.

### 1.1 우선 탐색할 산업 분야

지역 산업 탐색은 **조선·해양, 자동차, 항공, 방산, 수소·에너지, 데이터센터, AI, 2차전지**를 중심으로 구성한다. AI와 2차전지는 서로 다른 분야이므로 선택·데이터 태그를 구분한다. AI는 다른 산업과 함께 선택할 수 있다.

| 탐색 분야 | 창업 구상을 구체화할 질문의 방향 |
|---|---|
| 조선·해양 | 선박·해양 관련 업무 중 관심 있는 과정과 이용자 |
| 자동차 | 자동차·부품·정비 관련 업무와 필요한 서비스 |
| 항공 | 항공 관련 제품·업무·교육 중 관심 있는 접점 |
| 방산 | 방산 관련 기업의 일반 업무·교육·문서 등 지원 서비스 접점 |
| 수소·에너지 | 에너지 이용·관리·교육 관련 문제와 이용자 |
| 데이터센터 | 데이터센터 운영·관리 관련 업무와 이용자 |
| AI | 다른 산업의 어떤 업무에 AI를 적용하고 싶은지 |
| 2차전지 | 배터리 관련 생산·이용·관리·교육 중 관심 있는 과정 |

위 질문은 탐색 범주이며 실제 고객 불편·사업 기회가 확인됐다는 뜻이 아니다. 산업 이름을 선택한 것만으로 전문성·창업 적합성을 판정하지 않는다. 완성된 제품 제조뿐 아니라 해당 산업을 지원하는 소프트웨어·디자인·교육·업무 서비스까지 탐색할 수 있다.

‘아직 모름 / 기타 관심 분야’를 유지한다. 모든 산업을 동시에 구현하는 요구사항은 아니며, 실제 안내는 근거 자료와 지원 경로를 검수한 분야부터 제공한다. 각 분야가 부울경 모든 도시에 동일하게 집적돼 있다고 가정하지 않는다.

## 2. 문제정의와 근거 수준

### 2.1 우선 검증할 사용자 문제

> 창업에 관심은 있지만 경험이 없는 청년이 자신의 생각을 사업 용어로 설명하기 어렵고, 현재 단계에 필요한 준비와 이용 가능한 도움을 구분하지 못해 탐색을 중단한다.

이 문장은 사용자 인터뷰 전의 가설이다. 정보 부족, 용어 이해, 자신감, 자금 부족, 시간 부족을 같은 원인으로 묶지 않는다. 최근 창업 정보를 찾아본 사람이 어디에서 멈췄는지 확인해야 한다.

### 2.2 기존 기획에서 발견한 제품상의 모순

| 기존 구조 | 문제 | 수정 방향 |
|---|---|---|
| 상담 전에 사업·고객·수익 방식 입력 | 초보자가 상담으로 알아가야 할 내용을 선행 지식으로 요구 | 일상 언어로 입력하고 대화 중 구체화 |
| 가입해야 상담 시작 | 가치를 확인하기 전에 계정 생성 필요 | 핵심 흐름은 비회원 체험 |
| 지원사업 Top3와 자동 제출 중심 | 창업 준비 이전의 사용자를 바로 신청 단계로 이동 | 창업 구상·준비사항을 먼저 제시 |
| 지역 자체 공고는 P2 | 지역성을 설명할 핵심 자료가 선택 기능에 머묾 | 소수의 검수된 부산 경로를 P0 데이터로 확보 |
| 성향 테스트로 유형 부여 | 재미가 실제 준비 방향의 근거처럼 받아들여질 수 있음 | 초기 버전에서는 제외하고 현재 준비 상태를 확인 |

### 2.3 사회적 배경과 지역 문제의 구분

청년 일자리와 정착은 관심 배경이며, 이 웹서비스가 해커톤 기간에 해결했다고 주장할 성과는 아니다. 청년 유출의 원인이나 외국인 유학생 고용과 일자리의 관계는 검증된 근거 없이 제품 필요성에 사용하지 않는다.

창업 입문의 어려움은 전국 공통 문제다. 지역성은 지역 사용자가 겪는 장애물, 검수된 산업·상권의 배경, 지역 자원에 접근하는 과정을 함께 제시해 입증한다. 이번 변경은 부울경 창업 검토를 제품의 목표로 삼는 것이며, 실제 안내 범위는 확보한 자료로 제한한다. 부산 자료만 확보했다면 부산 시범 범위를 표시하고 울산·경남까지 지원한다고 표현하지 않는다.

### 2.4 추가로 검증할 지역 문제 가설

> 창업에 관심 있는 청년이 자신의 관심·역량을 부울경의 어떤 고객·산업·상권과 연결할 수 있는지, 그 구상을 지역에서 준비하려면 무엇을 활용할 수 있는지 파악하기 어렵다.

‘동남권만 존재하는 문제’라고 주장하지 않는다. 지역 산업이 있다는 사실은 해당 고객의 구매 수요나 초보자 창업의 적합성을 입증하지 않는다. 지역 기반·고객 가설·지원 접근 조건을 구분해 검증한다.

## 3. 사용자와 지원 범위

| 대상 | 상황 | 제공할 가치 |
|---|---|---|
| 주 사용자 | 창업 경험이 없고 관심 분야나 막연한 아이디어가 있음 | 생각 정리, 용어 설명, 우선 준비사항 |
| 탐색 사용자 | 관심은 있지만 아이디어가 없음 | 관심·경험을 바탕으로 검토할 방향을 제안하고 본인이 선택 |
| 보조 사용자 | 구상은 있고 교육·상담·지원이 필요함 | 관련 지역 경로와 조건 확인 |
| 초기 범위 밖 | 운영 중 기업의 전문 경영·투자·법률·세무 문제 | 해당 전문기관 안내, 일반 AI 상담으로 해결했다고 주장하지 않음 |

학교 재학 여부나 특정 연령대만으로 체험을 막지 않는다. 개별 지원의 연령·소속·사업자 요건은 해당 자료의 명시 조건에 따라 확인한다.

## 4. 제품의 차별화 가설

차별점 후보는 **내 관심 → 출처 있는 지역 문제 탐색 → 사용자가 선택한 방향 → 확인할 고객·시장 가설 → 실제 지역 준비 경로**의 연결이다. 팀이 수집·검수한 문제 자료와 사용자의 선택을 보존하는 탐색 과정이 핵심이다. 자료를 확보하지 못한 상태에서 일반 AI 대화와 차별화됐다고 주장하지 않는다.

| 비교 대상 | 공식 안내에서 확인한 제공 영역 | 우리 제품에서 검증할 추가 가치 |
|---|---|---|
| K-Startup | 창업 지원 공고와 신청 경로 | 공고를 고르기 이전에 필요한 구상 정리 |
| 창업에듀 | 아이디어 도출·아이템 검증·사업모델·계획서 등 단계별 교육 | 사용자의 상황을 먼저 정리하고 필요한 학습 경로로 연결 |
| 부산창업포털 연계 지원 | 상담·교육·공간 지원 안내 | 현재 단계에 맞는 이용 대상·절차·준비사항 설명 |

## 5. 핵심 사용자 흐름

메인 → 준비 상태·관심·검토 지역 입력 → 기존 화면에서 지역 문제 카드 탐색·선택(직접 입력·보류 가능) → 선택 이유와 경험을 쉬운 질문 최대 3개로 정리 → 사용자가 확인한 탐색 방향·구상 요약 → 준비사항·검수된 지역 지원 경로.

- 아이디어가 없으면 관심 분야와 경험을 출발점으로 삼는다.
- 모르는 답변을 허용하며 미확정 항목으로 남긴다.
- 사용자가 명시한 내용과 AI가 제안한 가설을 구분한다.
- 지원사업을 보고 싶을 때만 필요한 자격 정보를 추가로 받는다.
- 맞는 지역 경로가 없으면 없다고 안내하고 범용 준비 안내를 제공한다.

## 6. 기능 범위와 우선순위

기존 기능 ID를 유지한다. P0는 핵심 흐름, P1은 보완, P2는 이번 제품 범위 밖의 후속 검토다. 상세 규칙은 [features.md](features.md), 화면은 [web-pages.md](web-pages.md)에 따른다.

상태: 완료 = 운영 중, 시연 가능 = 동작하지만 자료·확인이 더 필요, 반영 중 = 이 변경과 함께 들어가는 중, 미구현.

| ID | 기능 | 우선 | 상태 |
|---|---|---|---|
| F0 | 회원가입·이메일 인증·로그인 (창업 준비 이용 전 필수) | P0 | 완료 |
| F1 | 준비 상태·관심 입력 및 지역 문제 선택 | P0 | 완료 (문제 카드 블록은 상담 화면에서 뺐다. 직접 적기는 유지. 지역은 한 칸 RegionPicker. 관심 공고로 시작 가능) |
| F2 | 쉬운 질문 기반 창업 탐색 | P0 | 완료 |
| F3 | 사용자 선택 기반 탐색 방향·창업 구상 요약 | P0 | 완료 |
| F4 | 공개 자료와 사용자 조건 대조 | P0 | 완료 |
| F5 | 단계에 맞는 교육·상담·지원 추천 | P0 | 완료 (규칙 거르기 + Solar Decide 순위. 관심 공고·하트·최근 본 공고 반영) |
| F6 | 관련 이유·미확인 조건 설명 | P0 | 완료 |
| F7 | 모집 상태·마감·확인일 관리 | P0 | 완료 |
| F8 | 실제 공고 수집·갱신 (K-Startup API) | P0 | 완료 (매일 03:00 KST) |
| F9 | 계정·현재 기기의 진행 상태 저장·초기화 | P0 | 완료 |
| F10 | 결과 유용성 피드백 | P0 | 완료 |
| F11 | 실제 지역 기관·이용 경로 | P0 | 시연 가능 (부산 교육·상담 7건) |
| F12 | 우선 준비사항과 후속 준비 안내 | P0 | 완료 |
| F13 | 지원서 초안 | P1 | 반영 중 (공고 양식 읽기 + Solar 초안. 상담 자료로 미리 채움. 계정당 7일 2회) |
| F14 | 팀 통계 화면 | P1 | 완료 (/admin, 메뉴 링크 없음) |
| F15 | 주거·교통 등 일반 청년지원 확장 | P2 | 미구현 |
| F16 | 외부 지원서 자동 제출 | P2 | 미구현. 모의 제출만 하고 실제 신청은 공식 사이트 |
| F17 | 제출 내역 | P1 | 반영 중 (내 정보의 내 지원서) |
| F18 | 공고·교육·상담 목록과 상세 | P1 | 완료 (페이지 5개 창, 정렬 select, D-n 배지, 지역 선택) |
| F19 | 창업 유형 테스트 (재미·참고용) | P1 | 완료 |
| F20 | 시작 안내 메인 | P0 | 완료 (해보까 포털 디자인, ‘처음이라면’ 순서 칩) |
| F21 | 검수된 지역 문제·맥락·지원 경로 데이터 | P0 | 부분 (경로 7건, 문제 카드·지역 맥락은 미확보) |

F13·F17 은 지원서 작성 기능으로 제품에 들어온다. 사용자가 확인한 초안을 모의 제출까지 하며, 외부 사이트 실제 제출(F16)은 하지 않는다. 성향 테스트는 재미·참고용으로 두고 핵심 성과와 분리한다.

## 7. 성공 기준과 검증

아래 수치는 팀 내부의 제안 목표이며 실측 성과가 아니다.

| 지표 | 제안 목표·방법 | 해석 |
|---|---|---|
| 대상 사용자 체험 | 10명 목표, 창업 경험·관심 상태 구분 | 참가자 전체를 대상 사용자로 간주하지 않음 |
| 흐름 완료 | 시작 대비 결과 도달 수·비율 | 가입 수로 대체하지 않음 |
| 자력 사용 | 직접 관찰한 사용자 중 도움 없이 진행한 수 | 모르는 항목에서 막히는지 기록 |
| 준비 방향 이해 | 결과 후 본인이 우선 준비사항과 이유를 설명할 수 있는지 | 체크박스 클릭과 별도로 관찰 |
| 접근성 체감 | 사용 전후 ‘무엇부터 준비할지 알고 있다’ 1~5점 | 문항·표본 수·변화량 함께 공개 |
| 지역 연결 | 공식 상세·문의·신청 링크 이동 | 클릭을 실제 상담·신청 완료로 부르지 않음 |
| 지역 창업 이해 | 사용 후 지역에서 검토할 이유와 미확인 조건을 각각 설명할 수 있는지 | 긍정 응답을 유도하지 않고 근거를 기록 |
| 자기주도 탐색 | 선택한 문제·관심 이유·확인할 가설을 스스로 설명할 수 있는지 | AI 제안 수나 선택 클릭만으로 이해를 인정하지 않음 |
| 지역 검토 의향 | 전후 동일 질문: ‘부울경을 창업 준비 지역으로 검토할 의향이 있다’ 1~5점, 응답하지 않음 허용 | 관심 변화이며 창업·정착 성과가 아님 |
| 구체적 지역 경로 확보 | 결과 후 이용 대상·절차를 포함한 지역 경로 하나를 말할 수 있는지 | 링크 클릭과 이해를 구분 |
| 데이터 품질 | 표시한 지역 경로 모두 출처·확인일 보유 | 마감 자료를 모집 중으로 오표시한 건수 기록 |

인상적인 답변 생성보다 사용자가 자신의 말로 설명하는지 확인한다. 사용 후에도 준비 방향이 불분명하면 질문과 결과를 수정한다. 작은 표본은 초기 사용성 검증으로 제시한다.

## 8. 데이터와 AI 요구사항

- 지원 자료와 별도로 공식 산업·상권 배경을 정리한 지역 맥락 자료를 소수 검수한다. 산업의 존재를 초보자의 사업 기회로 바로 단정하지 않는다.
- 첫 배포는 부산 지역 교육·상담·공간·지원 경로 5~10개를 목표로 수동 검수한다. 목표 수를 채우기 위해 자료를 만들지 않는다.
- 자료별로 공식 링크, 운영기관, 대상, 지원 내용, 이용 절차, 준비사항, 모집 상태, 기간, 확인일을 보유한다.
- 대학 프로그램은 외부인 이용 가능 여부를 확인한다. 기관 위치와 신청 가능 지역을 구분한다.
- API는 원문으로 연결하는 수단이며, 요약 필드만으로 모든 자격을 확인했다고 표시하지 않는다.
- 조건은 규칙으로 대조하고 AI는 설명·대화·구상 정리를 맡는다.
- 결과는 ‘입력 조건 부합 / 추가 확인 필요 / 명시 조건 불일치’. 부합은 최종 자격 보장이 아니다.
- 데이터나 사용자 답변이 없으면 unknown으로 유지한다. AI가 고객 수·수익성·지역 산업 연계·기관 서비스·모집일을 만들지 않는다.
- AI 실패 시 재시도와 함께 사용자가 직접 구상·준비사항을 정리할 수 있는 기본 양식을 제공한다.

## 9. 구현·운영 기준

- 기존 Cloudflare 배포와 국산 AI 활용 방향은 유지하되 특정 SDK를 제품 차별점으로 설명하지 않는다.
- 기존 비용 상한 방향을 유지한다. 플랜·포함량은 구현 시 공식 문서로 재확인하며 이번 문서는 최신 가격을 보증하지 않는다.
- 핵심 체험에 이름·연락처·비밀번호를 요구하지 않는다. 나이·소속 등은 선택한 지원의 조건 확인에 필요한 시점에 받는다.
- API 키는 서버에서 관리한다. 대화 전 서버·외부 AI 전송 범위를 알리고, 분석 이벤트에는 대화 원문을 넣지 않는다.
- 비회원 저장은 현재 기기에 한정하며 초기화 가능하게 한다. 결과를 자동 공개하지 않는다.
- 소규모 화면에서 한 번에 한 질문을 제공하고, 기술 용어는 일상 표현과 예시로 설명한다.

## 13. 추가 변경안: 기존 개발을 유지하며 부울경 창업 검토 유도

### 13.1 변경 원칙과 최소 적용 범위

이번 추가분은 기존 입력 → 대화 → 요약 → 추천 순서와 페이지 경로, 기능 ID, 배포 구조를 유지한다. 새 지도·기업 매칭·지역 순위·실시간 산업 분석은 만들지 않는다. 앞선 접근성 개정안 전체를 적용해야 지역성 보완을 할 수 있는 것은 아니다. 팀이 원래 폼과 로그인으로 개발 중이라도 아래 항목을 독립적으로 적용할 수 있다.

| 기존 기능 | 최소 수정 | 사용자에게 달라지는 점 | 구현 영향 |
|---|---|---|---|
| F1 입력 | 기존 지역 값을 재사용하고 ‘창업 검토 지역’ 선택을 선택항목으로 추가 | 거주지와 창업 희망지를 구분 | 폼·상태의 선택값 한 항목 |
| F2 대화 | 기존 최대 3개 질문 중 하나를 지역 접점 질문으로 교체 | 관심이 지역 경험과 연결됨 | 프롬프트·질문 선택 규칙 |
| F3 요약 | 기존 요약 아래 지역 검토 카드 1개 | 지역 기반·고객 가설·확인할 점을 구분해 봄 | 결과 객체 선택 필드·카드 |
| F5·F6 추천 | 기존 후보 중 목적·자격·단계가 맞는 지역 경로를 설명 | 왜 이 자원이 자신의 구상에 필요한지 이해 | 추천 이유·동순위 정렬 |
| F11·F12 안내 | 지역 공식 문의 경로와 문의할 내용을 연결 | 다음 준비와 기관 이용이 이어짐 | 기존 카드 내용 확장 |
| F21 데이터 | 산업 배경과 실제 이용 경로를 연결할 태그·출처 추가 | 확인된 지역 정보를 근거로 검토 | 소수 JSON/기존 데이터 확장 |

필수 추가는 선택 입력 1개, 질문 규칙 변경, 지역 검토 카드 1개와 근거 데이터다. P1인 목록 전체 개편·별도 통계 화면은 기다리지 않는다. 실제 비용은 현재 코드와 API 계약을 담당 개발자가 확인한다. 아직 구현되지 않은 UI·데이터를 완료된 기능으로 발표하지 않는다.

### 13.2 지역 검토 카드의 필수 논리

1. **지역에서 검토할 이유:** 공식 자료로 확인한 지역 산업·상권 배경과 사용자 관심의 접점. 독점적 강점이나 수익성으로 확대 해석하지 않는다.
2. **확인할 고객·시장 가설:** 누가 어떤 도움을 필요로 할 수 있는지 제안하고 미검증 표시.
3. **지역에서 준비할 경로:** 실제 이용 조건과 절차가 검수된 경로 ID·원문. 없으면 미확인 표시.

지역 배경과 창업 구상 간 연결이 약하면 ‘현재 자료로 지역 연관성을 판단하기 어려움’으로 표시한다. 사용자에게 분야나 검토 지역을 바꿀 선택권을 제공한다. 어떤 지역을 선택해도 같은 설명 뒤에 도시 이름만 바꾸는 방식은 허용하지 않는다.

### 13.3 지역 맥락 자료의 출처와 한계

공식 지역 배경 자료의 예시:
- [부산시 9대 전략산업](https://www.busan.go.kr/depart/ecnm9plan): 해양·미래모빌리티·에너지테크·디지털테크 등 관련 배경 확인.
- [울산시 투자환경](https://www.ulsan.go.kr/u/economy/contents.ulsan?mId=001012001002000000): 자동차·조선·석유화학 산업 기반 확인.
- [경남투자청 주력산업 안내](https://investgn.or.kr/whyGyeongnamInd/): 경남 산업 분야 탐색의 출발 자료.

위 자료는 산업 배경 출처이며 현재 모집 중인 프로그램·기업 협력·실증 기회·고객 수요의 증거가 아니다. 실제 이용 경로는 별도 공식 원문으로 검수한다. 첫 구현은 주제 1~2개와 사용자 사례 하나부터 시작하며, 전국·전 산업 또는 부울경 모든 지역의 완전한 대응은 목표로 삼지 않는다.

### 13.4 사용자 사례와 발표 범위

설명용 입력 예: ‘AI에 관심이 있고 조선·해양 분야의 업무를 지원하는 서비스를 살펴보고 싶다.’

- 공식 산업 배경을 근거로 지역 조선·해양 분야와의 접점을 설명할 수 있다.
- ‘관련 업체에서 반복적인 자료 정리를 지원할 필요가 있을 수 있다’는 고객 가설은 미검증으로 제시한다. 실제 문제·자료 이용 가능성은 별도로 확인한다.
- 실제 업체 수요·협력 가능 여부·예산을 확인할 질문을 안내한다.
- 검수한 교육·상담 경로가 있을 때만 이름과 이용 방법을 제시한다.

해커톤 성과는 ‘지역 창업 가능성을 검토하고 구체적인 준비 경로를 이해했다’까지 검증한다. 창업 건수·지역 정착·청년 유출 감소로 바꿔 말하지 않는다.

## 14. 추가 변경안: 사용자가 스스로 창업 방향을 탐색

### 14.1 기존 개발에서 수정할 지점

새 탐색 페이지·기업 문제 접수 플랫폼을 만들지 않는다. 기존 관심 입력 다음 또는 채팅 첫 영역에 문제 카드 묶음을 넣고 선택 정보를 기존 대화·요약·추천에 전달한다. 이 추가분은 계정·지원서·화면 전체 개편 없이 독립 적용할 수 있다.

| 기존 기능 | 최소 수정 | 제외할 범위 |
|---|---|---|
| F21 자료 | 출처를 검수한 지역 문제 카드 소수 작성 | 전 산업 수집, AI의 문제 사실 생성 |
| F1 입력 | 관련 카드 최대 3개, 1개 선택·직접 입력·보류 | 강제 업종·문제 선택 |
| F2 대화 | 선택 이유·자신의 경험·접근 관심 질문 | AI가 사업 아이템·해결책 확정 |
| F3 요약 | 선택 문제·관심 이유·직접 고른 방향·미확인 사항 | 창업 적성·성공률 점수 |
| F5·F6·F12 결과 | 선택 방향에 필요한 준비·지역 지원 연결 | 선택과 무관한 업종 추천 |
| F9·F10 상태·검증 | 선택·변경 저장, 자기주도 탐색 확인 | 선택 클릭을 구매 수요로 해석 |

### 14.2 사용자의 결정권

- 문제 카드는 탐색 재료이며 반드시 해결해야 할 과제가 아니다.
- 기존 아이디어를 우선한다. 다른 문제를 골라야 진행할 수 있게 만들지 않는다.
- 사용자가 도움을 원할 때만 접근 방향을 최대 2개 제안한다. AI 제안은 선택·수정 전 사용자 결정으로 기록하지 않는다.
- ‘다른 문제 보기 / 직접 적기 / 아직 탐색 중’을 허용하고 보류를 낮은 적성이나 실패로 표현하지 않는다.
- 결과는 ‘당신에게 맞는 사업’ 대신 ‘선택한 탐색 방향’을 보여준다. 고객·해결책·수익 구조는 미정이어도 된다.

### 14.3 문제 자료의 근거 수준

각 카드에 지역·산업·문제를 겪는 대상·발생 상황·기존 처리 방식·원문/인터뷰 근거·자료 시점·확인일·한계·미확인 사항을 포함한다.

‘인터뷰에서 확인 / 기사·공식 자료에 보고 / 조사 후보’를 구분한다. 기사에 실렸다고 현재까지 미해결이거나 돈을 내고 해결할 고객이 있다고 단정하지 않는다. 출처의 사실과 팀의 해석을 구분한다. 인터뷰 공개 동의·익명화 범위를 확인하고 비공개 정보를 카드에 싣지 않는다.

첫 버전은 분야 하나의 검수 카드 2~3개를 목표로 한다. 다른 산업 선택은 유지하되 해당 분야 자료가 없음을 표시하고 직접 탐색을 제공한다. 자료 부재를 AI 생성 문제로 채우지 않는다.

### 14.4 팀 완료 기준

관심 입력 → 근거 확인 → 문제 선택 → 선택을 보존하는 대화 → 수정 가능한 탐색 방향 → 준비·지원 연결까지 이어져야 한다. 다른 문제로 바꾸면 질문·요약·추천을 갱신한다. 문제를 선택하지 않아도 기존 대화를 계속할 수 있어야 한다.

이번 변경은 문서 명세다. 실제 문제 자료 수집과 UI·AI 구현은 별도이며 검수된 문제가 없으면 독자 현장 데이터를 확보했다고 발표하지 않는다.

## 15. 확장 아이디어: 현장 피드백을 통한 탐색 방향 수정

사용자가 선택한 창업 구상에 대해 현장에서 확인할 질문을 정리한다. 향후 참여에 동의한 지역 사업자·현장 경험자의 피드백을 연결해 사용자가 근거를 바탕으로 탐색 방향을 수정하도록 확장한다.

| 단계 | 범위·우선순위 | 완료로 인정할 내용 |
|---|---|---|
| 이번 핵심 | 기존 P0 탐색 흐름 유지 | 문제 선택·대화·구상·준비 경로가 작동 |
| 여력 있을 때 | F12 안의 선택 보완(P1): 현장 확인 질문 최대 3개·복사 | 선택 문제와 미확인 가설에 연결된 질문을 사용자가 검토·수정 |
| 참여자 확보 시 | 기획 담당자가 직접 진행하는 소규모 시범 검증 | 참여 동의·실제 답변·사용자 수정 기록을 구분해 남김 |
| 향후 확장 | P2: 검토 요청·응답 전달·구상 수정 연결 | 참여자·운영 방식·공개 범위 합의 후 별도 명세 |

질문 생성만으로 ‘현장 검증 완료’라고 표시하지 않는다. 실제 답변이 없는 상태는 ‘현장 확인 전’이다. 답변이 있어도 그 응답자의 경험 범위에서 확인된 것이며 시장 수요 전체나 사업 성공을 입증하지 않는다.

이번에는 멘토 매칭·예약·실시간 채팅·요청 자동 발송·외부 접수 시스템을 만들지 않는다. 시범 사례는 관계자를 확보한 경우에만 진행하고, 참여자가 없더라도 핵심 흐름 출시를 지연하지 않는다.

발표에서 현재 기능은 ‘현장에 확인할 질문을 정리한다’, 확장 계획은 ‘실제 피드백을 연결해 구상을 수정하도록 돕는다’로 구분한다. 실제 답변을 얻기 전 ‘현장 의견과 대조하는 기능을 구현했다’고 말하지 않는다.

## 17. 사용자 피드백 반영 (2026-11-27)

2026-11-27 시험 이용자 13명이 웹 서비스를 써 보고 의견을 남겼다. 개인 정보는 적지 않고 주제만 정리한다. 상세 표는 [features.md](features.md) 4-1절.

반영한 것:
- AI 창업 상담: ‘내 조건 확인’ 팝업이 저장값을 유지하도록 고쳤다. ‘어떤 문제를 더 알아보고 싶나요?’ 문제 카드 블록을 뺐다. 결과에 ‘다음에 할 일’, 접이식 구상 요약, 유형 필터 칩을 넣었다. 로그인 전 /mentor 는 이동 대신 소개를 보여 준다 (#100).
- 공고 목록: 페이지 5개 창, 정렬 select, 마감 7일 이내 D-n·오늘 마감 배지, 메인 ‘처음이라면’ 순서 칩 (#99, #102).
- 지역 선택: 지역 → 구·군 칩의 RegionPicker 를 공고 목록, 내 정보, 상담 시작(활동·검토 지역을 한 칸으로), 내 조건 확인에 적용. 거주지에 울산·경남 추가 (#101, #103, #104).
- 개인화: 공고 상세에서 관심 공고로 상담을 시작하고, 하트·최근 본 공고를 추천에 반영한다. 지원서 초안은 상담 자료로 미리 채우고 계정당 7일 2회로 제한한다 (#105).

반영하지 않은 것:
- 로드맵 강의 같은 콘텐츠 요청과 더 많은 분야: 콘텐츠 제작이라 이번 범위 밖.
- 질문을 더 세분화해 달라는 요청: 기존 ‘직접 적기’로 자세히 답할 수 있어 따로 만들지 않았다.
