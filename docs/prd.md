## 1. 한 문장

부산에서 창업하려는 청년이 가입 후 사업과 타겟 고객 정보를 폼으로 넣으면, AI 멘토가 되물어 아이디어를 다듬고 **지금 신청할 수 있는 부산 창업 지원사업 Top3**와 찾아갈 기관, 첫 7일 실행 계획을 근거와 함께 알려준다. 사용자가 지원서 초안을 확인하고 승인하면 **AI 에이전트가 지원서를 대신 제출**한다.

## 2. 배경과 문제

### 2.1 지역 문제

- 부산은 청년 유출이 지역 핵심 현안이다. 지역에서 일자리를 **만드는** 경로(창업)가 그 대응 중 하나다. *(통계 출처 확인 필요)*
- 창업 지원사업은 많지만 창업진흥원(K-Startup), 부산시·구, 지원기관, 대학 창업지원단으로 **흩어져** 있다.

### 2.2 사용자가 겪는 문제

| # | 문제 | 지금 하는 방식 |
|---|---|---|
| P1 | 내 아이디어로 **지원할 수 있는 사업을 모른다** | 여러 사이트를 직접 검색, 지인에게 물어봄 |
| P2 | 공고의 **자격 조건**(나이, 창업 연차, 지역)을 읽고 해당 여부를 판단하기 어렵다 | 공고 PDF를 끝까지 읽음, 문의 전화 |
| P3 | 아이디어가 **정리되지 않아** 지원서를 시작하지 못한다 | 혼자 고민, 유료 컨설팅 |
| P4 | **다음에 무엇을 해야 할지** 모른다 | 멘토를 찾지만 연결이 어려움 |
| P5 | 사업마다 **같은 정보를 다른 양식에 반복 입력**해야 해서 지원을 미루다 마감을 놓친다 | 사이트별로 직접 입력, 복사·붙여넣기 |

### 2.3 왜 지금, 왜 AI인가

- 사람 멘토링은 24시간 안에 만들 수도, 모두에게 제공할 수도 없다 → AI가 1차 멘토 역할.
- 범용 AI는 **부산 지원사업과 마감일을 모른다** → 실제 공고 데이터에 근거해야 차별점이 생긴다.
- 추천에서 끝나면 사용자는 여전히 지원서를 직접 써서 내야 한다 → **AI 에이전트가 작성부터 제출까지** 이어 주면 "찾기"가 "지원 완료"로 바뀐다.

## 3. 사용자

| 페르소나 | 상황 | 원하는 것 |
|---|---|---|
| **예비 창업 대학생** (주 사용자) | 아이디어는 있지만 사업자 없음, 만 20~29세 | "내 아이디어로 받을 수 있는 지원이 있나?" |
| **초기 창업자** | 사업자 1~2년 차, 부산 소재 | 마감 전에 놓치지 않고 맞는 사업 찾기, 지원서 빨리 내기 |
| **해커톤 참가자** (검증 대상) | 이번 해커톤 아이디어를 실제 창업으로 이어가고 싶음 | 자기 해커톤 아이디어로 바로 체험 |

**대상이 아닌 사람:** 중견기업, 투자 유치 단계 스타트업, 부산 외 지역만 대상인 사람(확장 범위).

## 4. 목표와 비목표

### 4.1 목표

- G1. 사용자가 **3분 안에** 지원 가능한 부산 창업 지원사업 Top3를 근거와 함께 받는다.
- G2. 마감된 사업은 **추천하지 않는다**. 새 공고는 매일 반영된다.
- G3. 로그인한 사용자의 대화를 기억해 다시 방문하면 **이어서** 추천받는다.
- G4. 해커톤 기간 중 **실제 가입 사용자 10명 이상**에게 검증한다.
- G5. 사용자가 **승인한** 지원서를 AI 에이전트가 제출하고, 제출 결과(접수 확인 화면·번호)를 사용자에게 보여준다.

### 4.2 비목표 (만들지 않음)

- 사람 멘토 연결·예약, 결제
- **사용자 승인 없는 제출** (에이전트는 최종 제출 전에 항상 사용자 승인을 받는다)
- 본인인증·공동인증서·CAPTCHA 우회 (해당 단계가 있으면 사용자에게 넘긴다)
- 서류 파일(사업자등록증 등) 자동 발급
- 부산 외 지역 (울산·경남은 확장 후보)
- 법률·세무 자문

## 5. 성공 지표 (발표용 수치)

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 사용자 수 | 10명 이상 | 가입 사용자 수 |
| 새 지원사업 발견율 | 60% 이상 | 결과 화면 질문 "몰랐던 지원사업을 찾았나요?" |
| 추천 관련도 | 70% 이상 "관련 있음" | 추천 카드별 관련 있음/없음 버튼 |
| 소요 시간 | 3분 이내 | 첫 입력 → 결과 화면 시간 |
| 마감 사업 추천 | 0건 | 결과에 마감 지난 사업이 없는지 점검 |
| 제출 성공률 | 80% 이상 | 승인된 제출 중 접수 확인까지 끝난 비율 |
| 승인 없는 제출 | 0건 | 제출 기록마다 승인 기록이 있는지 점검 |

## 6. 사용자 흐름

```text
(진입) 메인 / 공고 모음 / 창업 유형 테스트 — 로그인 없이 사용
⓪ 회원가입·로그인(이메일·비밀번호)
→ ① 사전 상담 폼(나·사업·타겟 고객) → ② AI 멘토 챗봇 되묻기(3개) → ③ 아이디어 1장 요약
→ ④ 지원사업 Top3 + 찾아갈 기관 → ⑤ 첫 7일 실행 계획
→ ⑥ 사업 선택 → 공고 양식 내려받기 → 양식에 맞춘 지원서 작성 → 사용자 검토·수정 → 승인
→ ⑦ 에이전트 제출(진행 상황 표시) → 접수 확인 결과 저장
                 ↳ 카드별 "관련 있음/없음" 평가 → 다음 추천에 반영
(재방문) 로그인 → 이전 대화 이어서 → 새 공고 반영된 추천 + 제출 내역
```

### 7.1 기능별 수용 기준

- **F0** 이메일·비밀번호로만 가입한다. 로그인하지 않으면 ① 이후 화면에 들어갈 수 없다. 비밀번호는 평문으로 저장하지 않는다. 로그아웃하면 세션이 끝난다. 다른 계정의 데이터는 보이지 않는다.
- **F1** 필수 항목 없이 다음 단계로 넘어가지 않는다. 아이디어는 200자 이하. 섹션마다 자동 저장한다.
- **F2** 질문은 정확히 3개, 사용자가 "건너뛰기"를 할 수 있다.
- **F4** 판정 결과는 가능 / 확인 필요 / 불가 3단계. 조건 정보가 공고에 없으면 "확인 필요".
- **F5** 마감 지난 사업, "불가" 판정 사업은 Top3에 나오지 않는다. 각 카드에 원문 링크가 있다.
- **F6** 이유는 공고 내용과 사용자 요약에만 근거한다. 공고에 없는 금액·조건을 만들지 않는다.
- **F7** 한국 시간 기준으로 판단한다. 마감일이 없는 상시 모집은 제외하지 않는다.
- **F16**
  - 공고마다 그때 올라와 있는 신청 양식을 내려받아 쓴다. 미리 만든 고정 양식에 의존하지 않는다.
  - 내려받은 양식의 항목·글자 수 제한에 맞춰 작성하고, 채운 파일을 사용자가 미리 볼 수 있다.
  - 최종 제출 버튼은 사용자가 화면에서 **승인**한 뒤에만 누른다. 승인 내용(제출할 값 전체)과 시각을 기록한다.
  - 승인 후 제출 전에 마감이 지나면 제출하지 않고 알린다.
  - 같은 사업에 같은 계정으로 두 번 제출하지 않는다.
  - 본인인증·CAPTCHA·파일 첨부 등 에이전트가 처리할 수 없는 단계가 나오면 멈추고, 사용자가 직접 할 수 있도록 원문 링크와 입력값을 넘긴다.
  - 진행 단계(양식 열기 → 입력 → 승인 대기 → 제출 → 확인)를 실시간으로 보여준다. 실패하면 이유를 보여준다.
  - 제출 후 접수 확인 화면(캡처)과 접수 번호(있으면)를 저장한다.

## 8. 데이터 요구사항

### 8.1 지원사업 공고 (확인 완료)

| 항목 | 내용 |
|---|---|
| 출처 | 공공데이터포털 「창업진흥원_K-Startup(사업소개,사업공고,콘텐츠 등)_조회서비스」 |
| 기능 | `getAnnouncementInformation02` (지원사업 공고 정보) |
| 조건 | 무료, 개발계정 자동승인, 개발 트래픽 10,000건 |
| 주요 필드 | 공고 번호 `pbanc_sn`, 공고명 `biz_pbanc_nm`, 기관 `pbanc_ntrp_nm`, 지원 분야 `supt_biz_clsfc`, 지역 `supt_regin`, 접수 시작·종료 `pbanc_rcpt_bgng_dt`·`pbanc_rcpt_end_dt`, 모집 진행 `rcrt_prgs_yn`, 신청 대상 `aply_trgt`, 창업 연차 `biz_enyy`, 대상 연령 `biz_trgt_age`, 지원 내용 `support_ctnt`, 상세 링크 `detl_pg_url` |
| 필터 | 지역 `supt_regin`, 모집 중 `rcrt_prgs_yn=Y`, 연령·연차·대상 |

- **부산 공고 + 전국 공고**를 함께 받는다. 전국 대상 사업도 부산 창업자가 신청할 수 있기 때문이다. (전국 공고의 지역 값 표기는 실제 응답으로 확인 필요)
- 마감일 형식은 실제 응답으로 확인한다.
- 부산시·구·대학 자체 공고는 **우선 제외**한다. 시간이 남으면 수동으로 10개 정도 추가한다(F21, P2).

### 8.2 제출 대상 양식

- 제출 대상 사업과 양식은 **미리 고정하지 않는다**. 사용자가 고른 공고에 그때 올라와 있는 신청 양식을 사용한다.
- 에이전트는 Cloudflare **Container**에서 공고 상세 페이지(`detl_pg_url`)의 첨부 신청 양식(HWP·HWPX·DOCX·PDF 등)을 내려받고, 양식의 항목·글자 수 제한을 읽어 항목 목록을 만든다.
- 항목 목록에 맞춰 초안(F13)을 만들고, 사용자 승인 후 **원래 양식 형식 그대로** 채운 파일을 만든다.
- 공고의 **신청 경로**(K-Startup 온라인 접수, 기관 사이트, 웹 양식, 이메일 접수)를 읽어 그 경로로 제출한다. 웹 경로는 Browser Rendering으로 입력·파일 첨부, 이메일 경로는 채운 파일을 첨부해 보낸다.
- 신청 사이트 로그인·본인인증·CAPTCHA가 필요하면 `사용자 조치 필요`로 멈추고, 채운 파일과 원문 링크를 사용자에게 넘긴다.
- 시연 안정성을 위해 **팀이 만든 모의 접수 양식**을 백업으로 둔다.

### 8.3 사용자 데이터

- 저장: 계정(이메일, 비밀번호 해시), 프로필(나이, 창업 단계, 업종, 아이디어), 대화, 대화 요약, 추천 평가, 지원서 초안, 승인 기록, 제출 기록·접수 확인, 내려받은 공고 양식과 채운 양식 파일.
- 지원서 제출에 필요한 신원 정보(이름, 연락처, 이메일)는 **사용자가 직접 입력한 경우에만** 저장하고, 서버에서 암호화한다.
- 저장하지 않음: 주민번호, 공동인증서, 외부 사이트 비밀번호.
- 가입 화면에 "정보는 추천 개인화와 사용자가 승인한 지원서 제출에만 사용, 행사 후 삭제" 안내와 동의 체크.
- 사용자가 계정을 삭제하면 모든 데이터를 지운다.

## 9. AI 요구사항

| 역할 | 요구사항 | 후보 |
|---|---|---|
| 멘토 대화·요약·계획·초안 | 자연스러운 한국어, 응답 10초 이내 | 국산 AI (Solar / HyperCLOVA X) — 30분 비교 후 결정 |
| 관련도 점수 | 실제 후보 중에서만 고르고 확률 제공, 1초 이내 | jev (typesafe.ai) 공개 서비스 — 사용 가능 확인 완료, 한국어·후보 수 한도 테스트 필요 |
| 지원서 제출 에이전트 | 공고 양식을 내려받아 항목을 읽고 채움, 단계별 상태 유지, 승인 대기 후 재개 | Cloudflare Agents SDK(agent worker, Durable Object 상태) + Containers(양식 내려받기·변환·작성) + Browser Rendering(웹 접수) |
| 품질 검수 | 공고 데이터 오류 점검, 모델 비교 채점 | OpenAI·Claude (미리 하는 작업에만, 실시간 X) |
| 자격 판정 | 정확·일관 | **AI 사용 안 함 (규칙)** |

- AI가 공고에 없는 사업·금액·마감일을 **만들어 내면 안 된다**.
- AI 장애 시에도 Top3는 규칙 점수로 나와야 한다.
- 에이전트는 **사용자가 승인한 값만** 입력한다. 승인 뒤 값을 바꾸지 않는다. 양식에 승인되지 않은 필수 항목이 있으면 멈추고 사용자에게 묻는다.
- 에이전트 장애 시 사용자에게 원문 링크와 입력값(복사용)을 보여준다.
